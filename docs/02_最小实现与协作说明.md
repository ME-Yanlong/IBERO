# IBERO 最小实现初步协作说明

> 版本 v1.0 ｜ 2026-09-06 ｜ 用途：团队开工讨论材料
> 唯一验收目标：**双臂机器人抓取柔性线束，放到另一边**，6 周全链路跑通。

---

## 一、这个项目是什么：一个"机器人学做饭的培训基地"（比喻）

把 IBERO 想成一家**厨师培训学校**，教的是"双臂机器人学做工业操作"：

| 层 | 比喻 | 实际是什么 |
|---|---|---|
| **IBERO-Core** | **公共厨房**：灶台、刀、锅、电子秤、温度计 | 仿真物理世界 + G1 双臂机器人 + 力传感器 + 相机 + 控制算法，打包成可调用的软件库 |
| **IBERO-Suites** | **菜谱**："抓线束放到另一边"就是一道菜 | 场景定义：工件摆哪、怎么做算成功、哪些做法算违规（力太大=糊锅） |
| **ibero-record** | **摄像机拍大厨做 50 遍** | 录示范数据给学生（策略模型）学 |
| **ibero-cli** | **厨房管理员**：新菜谱登记、食材检查 | 命令行工具：校验场景、启动采集 |
| **IBERO-Eval** | **考试评分**：不止"菜上没上桌"，还要看"土豆丝断了几根、锅铲撞锅几次" | 成功率 + 无损率 + 内力超限率 + 自碰撞率 |

**一个外校研究者用我们的平台，只写三行：**

```python
env = ibero.make("cable_handover")        # 打开"抓线束"这道菜
obs = env.reset()                          # 摆好随机初始状态，返回相机图像+力觉
obs, reward, done, info = env.step(动作)   # 机器人动一步，返回新图像、是否完成、是否违规
```

他不需要知道 MuJoCo、柔性体、力传感器、渲染的任何底细——**IBERO-Core 就是供别人调用的集成工具（SDK）**。

### 什么是"重复造轮子"：轮子 vs 车身

**现成的轮子（直接用，谁再造谁是傻子）：**
物理引擎 MuJoCo（重力/碰撞/摩擦）、渲染器（虚拟相机拍照）、G1 机器人模型（宇树官方发布在 MuJoCo Menagerie）、控制算法 OSC/IK（robosuite 有现成部件可移植）、数据格式与训练框架 LeRobot、策略代码 ACT/DP。

**我们自己造的车身（别人没有、必须自己做的）：**
① G1 改造：把行走人形裁成"固定工位双臂"+挂夹爪+装相机；② 双臂环境：收"两臂动作"、出"三路图像+两腕力觉"；③ 柔性线束的物理标定：调到仿真线缆软硬与真实工业线束一致；④ 工业判定：什么算成功、什么算拉坏、什么算两臂打架。

> 引擎、格式、模型、算法都是轮子；"双臂+力觉+柔性体+工业判定的标准环境"是车身，这正是 IBERO-Core。

### 这家基地要开张，四个人怎么分工（会议速记版）

- **P1 水电工**：让厨房的水电标准化——谁进来插上电就能用（Gymnasium/LeRobot/ROS 2 统一接口与数据）
- **P2 机械师**：把一台会走路的机器人（G1）改装成固定在工位上的双臂厨师（裁剪、挂夹爪、装相机、接控制）
- **P3 材料专家**：研究"面条"（柔性线束）怎么仿真才像真的——软硬、韧劲（物理标定）
- **P4 菜谱作者**：写出第一道菜"把面条抓起来放到对面盘子"，并规定什么算熟了、什么算煮断了（场景 + 成功/损伤判定）

## 二、最小目标与完成定义（DoD）

**目标**：6 周内，`ibero.make("cable_handover")` 场景全链路跑通——建模 → 50 条脚本示范 → LeRobot 数据集 → ACT 训练 → 四项指标评测。

**完成定义（全部满足才算完成）**：

1. 三行代码演示可用：任何有 Python 基础的人 `pip install` 后即可 reset/step 该场景
2. 50 条脚本示范成功录制为 LeRobot 数据集，**不改代码**可被 `lerobot` 训练入口读取
3. ACT 训练收敛，固定评测协议下成功率 **≥ 60%**（阈值开会定）
4. 评测输出 `metrics.json`：成功率 / 线束无损率 / 拉力超限率 / 双臂自碰撞率
5. 线束物理标定报告：仿真行为与对标数据（实测或文献）误差在约定容差内
6. 交付演示视频 + README 快速开始文档

## 三、最小场景全流程（所有人对齐用）

**第 0 步：写菜谱（P4，场景层）**

```yaml
# scenes/cable_handover/scene_config.yaml
robot: g1_upperbody_2f85        # IBERO-Core 预置构型
objects:
  - type: cable                 # 一根柔性线束
    model: cable_60cm           # 几何 + 已标定材料参数
    init_region: table_left     # 初始摆在桌面左区（带随机偏移）
goal:
  In cable table_right_region   # 线束进入右边目标区 = 成功
constraints:
  wrench_max: 12.0              # 任腕拉力超 12 N → 记为损伤违规
```

**第 1 步：Core 把菜谱变成"能动的世界"（P2 + P3）**：装机器人（裁剪+夹爪+相机）→ 装工件（线束 = MuJoCo Flex 软体，用已标定材料）→ 把 goal/constraints 翻译成判定器。

**第 2 步：策略跑起来（外部用户视角，P1 提供接口）**：20 Hz 收 14 维动作（两臂末端增量+夹爪）→ 内部 OSC 换算成关节目标、500 Hz 推物理（线束弯曲、接触、力传感器读数）→ 渲染三路相机图 → 判定成功/损伤/碰撞 → 返回观测+审计。

**第 3 步：录示范、训练、评分（P1 + P4）**：脚本化控制器生成 50 条示范 → LeRobot 数据集 → LeRobot 训练 ACT → 50 个固定初始态评测 → 四项指标。

## 五、四份任务书

### P1 统一数据与动作接口（1 人）——水电工

**使命**：让"厨房水电"标准化——外部用户三行代码即可使用；内部四个人的数据都能流起来。

**做什么**：
- 定义并维护 **Schema v0**：动作空间（EE 增量 14 维 @20 Hz）、观测 key（三相机 + 两臂 proprio + 两腕 wrench 6+6）、info 审计流（damage_flags / self_collision_flags / contact_events）
- 把 P2/P3 的环境骨架封装为 `IBeroEnv(gymnasium.Env)`（官方 gymnasium，不用 BiGym 的 fork）
- LeRobot 适配器：env 轨迹 ↔ LeRobot 数据集双向（写出 / 回放），双臂与 wrench 扩展 key 文档化
- 评测协议：固定 50 个初始态（LIBERO pruned_init 机制移植）、四项指标统计、输出 `metrics.json`
- ROS 2：**只冻结 topic/msg 契约文档**（`docs/ibero_ros2_contract.md`），不写节点

**不做什么**：不写控制器、不碰物理参数、不定义场景内容。

**参考**：gymnasium 官方文档与 `env_checker`；LeRobot 数据集类源码；LIBERO 的 `pruned_init` 加载与评测循环；BiGym `bigym_env.py` 的 obs/action 约定。

**交付物**：`ibero-core/envs/`、`ibero-core/schema/`、`ibero-core/data/lerobot_adapter.py`、`ibero-eval/metrics.py`、ROS2 契约文档。

**验收**：① `env_checker.check_env` 通过、reset 20 种子可复现；② 50 条脚本示范→LeRobot 数据集→**不改代码**进 lerobot 训练 ACT；③ 数据集回放位姿误差 < 1e-4；④ `metrics.json` 含四项指标；⑤（协办）DoD 第 6 条 README。

### P2 机器人构型与双臂控制（物理组甲，1 人）——机械师

**使命**：把 Menagerie 的 G1 人形改装成"固定工位双臂厨师"，并让它听话（控制器）。

**做什么**：
- G1 构型改造（复用 BiGym 改造模式）：运行时裁剪掉腿/腰（weld 骨盆到工位基座）、挂装 Robotiq 2F-85 ×2（Menagerie 现成 XML，BiGym 挂装方式移植）、加 3 台虚拟相机（头部 + 双腕，G1 原生无相机）
- 双臂控制器：**首选 mink（MuJoCo 专用 IK 库，Apache-2.0）+ G1 原生 position 执行器（kp=500）**，EE 增量动作 → IK → 关节目标；robosuite `osc.py` 力矩级控制为备选后置；双臂自碰撞检测（MuJoCo 接触对检测）
- 实现 `PhysicsBackend` 的构型侧：模型装配、动作执行、渲染
- 提供"OSC 规划路径"能力供 P4 写脚本示范生成器

**不做什么**：不调线束等工件物理参数（P3）、不定义成功条件（P4）。

**参考**（许可证均已核实）：BiGym `robots/configs/h1.py`（裁剪模式）、`robot.py`（挂夹爪）、`envs/xmls/robotiq_2f85/2f85.xml`（Apache-2.0）；MuJoCo Playground `locomotion/g1`（G1 常量/配置，Apache-2.0）、`manipulation/aloha`（EE 控制模式）；**mink**（Apache-2.0）；Menagerie `unitree_g1/g1.xml`（BSD-3-Clause，保留版权声明）；robosuite `controllers/parts/arm/{osc,ik}.py`（MIT，备选）。

**交付物**：`ibero-core/robots/`（g1_upperbody_2f85 构型）、`ibero-core/controllers/`（OSC/IK）、PhysicsBackend 构型侧实现。

**验收**：① 构型可完整驱动 14+2 DoF；② 500 Hz 无渲染仿真实时率 ≥ 5×；③ 夹爪开合可稳定抓取刚性测试件（先验证刚性，再交给 P3 上线束）；④ 双臂自碰撞检测触发正确。

### P3 接触力学与柔性体标定（物理组乙，1 人）——材料专家

**使命**：研究"面条"——让仿真线束的软硬、韧劲、可抓性接近真实工业线束，并给出损伤判定依据。

**做什么**：
- 线束建模（两步走）：先用 **composite capsule 链**打通抓放（当天可跑、风险最低），再升级到 **MuJoCo 3.x elasticity 插件原生 `cable` 元素（FEM 线缆）**做保真标定；建立 `cable_60cm` 等**已标定材料资产**（密度/弯曲刚度/摩擦/接触参数），写成可复用参数文件
- 标定闭环：搭"悬垂/弯折"标定小场景，仿真行为与对标数据比对（实测线束优先，否则用线束厂商 datasheet/文献），误差写入 `docs/calibration_cable.md`（fidelity envelope）
- 力觉：两腕 F/T 传感器（MuJoCo site force/torque）+ 静载校验（悬垂已知重量，误差 < 5%）
- 损伤判定：实现 `wrench_max` 等约束语义的判定器（力超阈值 → info.damage_flags），供 P4 在 YAML 中声明
- 实现 `PhysicsBackend` 的工件侧：物体装配、接触对配置、求解器参数

**不做什么**：不改机器人构型（P2）、不写策略与数据（P1）、不写场景内容（P4）。

**参考**：MuJoCo `plugin/elasticity/cable.{cc,h}` 与官方示例（原生 FEM 线缆）；composite 官方示例；LIBERO 无此能力（自研）。

**交付物**：`ibero-core/physics/`（PhysicsBackend 工件侧 + 材料库）、线束资产与标定报告、损伤判定器。

**验收**：① 线束可被双臂稳定抓起、放下（联合 P2 集成）；② 标定报告给出对标数据与误差、误差在约定容差内（开会定）；③ F/T 静载校验误差 < 5%；④ 拉力超阈值时损伤标志正确触发。

### P4 场景与菜谱（1 人）——菜谱作者

**使命**：写出第一道菜，定义"成功"与"违规"，并产出学生教材（脚本示范）。

**做什么**：
- 定义**场景 YAML 规范 v0**（robot / objects / goal / constraints 字段语义与取值范围），落地 `scenes/cable_handover/`（scene_config.yaml + task_spec.py + assets + constraints.yaml）
- 判定器：`_success()` = 线束入目标区 + 双夹爪已释放 + 无损伤标志；对齐 P3 的损伤判定器与 P1 的审计流字段
- 脚本示范生成器：基于 P2 的 OSC 规划接口生成 50 条示范（覆盖不同初始位姿/弯度），保证成功率 ~100%（脚本可复现）
- 固定 50 个评测初始态（配合 P1 的 pruned_init 机制，负责"哪些初始态合法可解"的筛选）

**不做什么**：不实现控制器（P2）、不调物理参数（P3）、不写训练代码（P1）。

**参考**：LIBERO BDDL 示例与谓词语义（`On/In` 等，作为 YAML goal 的语义来源）；BiGym 任务类模式（env 子类 + `_success()` 物理条件）。

**交付物**：场景 YAML 规范 v0 文档、cable_handover 场景全套、脚本示范生成器、初始态集。

**验收**：① `ibero check --scene cable_handover` 通过（与 P1 的校验器对接）；② 50 条脚本示范在固定初始态上复现成功率 100%；③ 场景经外部三行代码即可加载。

## 七、开会讨论要点（本文件需要拍板的地方）

1. **构型确认**：G1 固定上身 + Robotiq 2F-85（本文件默认）；是否坚持 Dex3-1 灵巧手（首期不建议）
2. **线束对标数据来源**：实验室有无真实工业线束可实测？没有则用厂商 datasheet/文献（P3 需要这个资源承诺）
3. **ROS 2 首期只冻结契约不写节点**：是否同意（建议同意）
4. **ACT 成功率验收阈值**：≥ 60% 是否合理
5. **仓库策略**：先 GitHub 私有跑 6 周，还是直接公开（建议私有→W6 后公开）
6. **GPU 资源**：服务器账号、训练所需显存（ACT 单卡 24 GB 足够）落实
7. **人手风险**：若实际不足 4 人，P2+P3 可合并（但标定任务顺延 2 周）；若 P1 任务最紧，评测协议可后移给 P4 分担

## 八、风险与兜底

| 风险 | 兜底 |
|---|---|
| 线束抓取不稳（Flex-rigid 接触调参难） | 先给线束加硬质端子帽，抓端部；再逐步放开抓中段 |

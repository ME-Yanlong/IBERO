# Core-0.1 工业材料与加工机制：卡扣解锁、切削去除与下一阶段架构

## 1. 结论：先建立可验证的工业机制，再扩充任务数量

IBERO 下一步最值得投入的，不是再增加几个不同外观的抓取场景，而是增加两类会改变操作结果的底层机制：**变形引起的机械解锁**，以及**加工引起的永久材料去除**。它们能够把平台从“操作会移动的物体”推进到“操作具有内部结构、加工历史和失效边界的工业对象”。

建议继续在 Core-0.1 下开展机制原型和验证。先完成卡扣的弹性接触解锁，再完成固定工件的铣削去除闭环；只有当材料、接触、加工力、碰撞和回放形成可复用的整体，才把这一能力跃迁定义为 Core-0.2。版本号不应由场景数量或者视觉效果决定。

技术路线不是“纯物理”与“纯规则”二选一。推荐采用**经过标定、有明确适用范围的混合模型**：

- 卡扣：接触力驱动弹性结构变形，真实扣合几何决定能否退出；状态机记录锁止和释放，不替代机械因果。
- 铣削：刀具与工件的相对运动决定候选去除区域，加工模型提供载荷与能力边界，持续更新剩余材料、碰撞和孔槽；切屑显示作为独立保真层。
- 高精度有限元：用于局部问题分析和模型标定，不默认承担整台双臂机器人每一步的在线仿真。

这两类能力非常适合 IBERO 的方向，但“只有同时模拟卡扣和铣削才能称为工业平台”不是必要条件。工业平台的可信度来自声明清楚的工艺范围、可重复的验证和可追溯的误差，而不是覆盖所有制造过程。现阶段最应避免的是把“看起来能加工”表述成“已具备工业加工预测精度”。

第 1—12 节为研究依据，不代表新增组件已经实现；第 13—17 节执行计划已于 2026-09-10 获用户批准，实际进度见第 18 节。外部资料核查截至 2026-09-10；本地实现以当前源码为准，MuJoCo 以项目固定的 3.8.1 为准。`latest` 文档只用于候选技术评估，不能视为已在本项目验证。

执行入口：文末 [第 13 节：详细执行任务计划](#13-core-01-工业机制扩展详细执行任务计划已批准)，以及第 14—17 节的量化门槛、文件落点、连续工作规则和批准范围。第 1—12 节保留研究依据；第 18 节记录实际执行证据。

## 2. 与最初建设方案和现有代码的关系

原始《IBERO__工业级双臂具身智能操作基准平台建设方案》在 2.2 和 4.1 节已经明确提出柔性线缆动力学、卡扣形变阻力、微形变恢复力、卡扣释放突变力、微间隙接触，以及双臂力位协同。因此，卡扣不是偏离方向的新需求，而是当前最应该补上的原始 Core 能力之一。钢板切割、铣削及材料去除则进一步扩展了当前种子场景范围，需要独立的加工机制，不能直接当作线束材料的一个参数选项。

当前代码已有基础，但仍是线束任务导向的实现：

| 位置 | 已有职责 | 对下一阶段的意义 |
| --- | --- | --- |
| [pyproject.toml](../pyproject.toml) | 固定 MuJoCo 3.8.1，项目版本 0.1.0 | 新能力优先在这个明确版本上验证 |
| [materials/cable.py](../src/ibero/materials/cable.py) | 线束参数、几何构建、Flex 与端头连接、编译后句柄 | 可复用“参数→模型→句柄”的组织方式，不能直接充当通用实体材料 |
| [materials/mechanics.py](../src/ibero/materials/mechanics.py) | 轴向边弹簧张力、中心线弯曲能及其负梯度力 | 已有实际力学计算，不只是绳子动画；但不是三维实体应力模型 |
| [materials/bench.py](../src/ibero/materials/bench.py) | 线束材料台架 | 适合扩展“先材料台架、后机器人任务”的开发模式 |
| [core/scene_compiler.py](../src/ibero/core/scene_compiler.py) | 场景到 MuJoCo 模型的编译入口 | 当前仍直接依赖 G1 handover 构建器与 CableParameters，尚未通用化 |
| [core/sensors.py](../src/ibero/core/sensors.py)、[core/audit.py](../src/ibero/core/audit.py) | 传感与审计 | 以后需要区分接触力、材料内力、加工力和传感器读数 |
| [review.py](../src/ibero/review.py) | 保存和恢复 MuJoCo 积分状态及审计信息 | 当前不保存未来新增的材料占据场、加工历史和变更后的模型拓扑 |

现有 Flex 线束包含轴向弹性和自定义弯曲响应；`bending_energy_force()` 明确采用无扭转中心线模型。它没有因此自动获得塑性、裂纹、实体局部压痕或任意切割能力。线束报警阈值也不等价于断裂模型：报告超限，与计算断裂后分成两个对象，是不同层次的功能。

同样，“填写了长度、密度、弯曲半径等信息，所以就应该自动使用 Flex”需要进一步收紧。场景应当允许自定义这些物理量，但**模型选择还取决于目标现象和可识别参数**。只提供弹性模量与密度，不足以预测钢材切削；只提供一条按压曲线，也不足以预测任意方向下的卡扣破坏。

## 3. 两个问题，本质上是哪两类能力

| 对比项 | 按压卡扣后拔出 | 铣削或切割钢板 |
| --- | --- | --- |
| 主要变化 | 结构变形，扣合关系改变 | 材料永久去除，边界或连通关系改变 |
| 典型状态 | 弯曲量、接触位置、锁止重叠、残余变形 | 剩余材料、刀具啮合、已去除体积、分离块 |
| 最重要的因果 | 按压→弹性变形→倒扣让开→可以拔出 | 刀刃有效运动与载荷→材料去除→孔槽及接触改变 |
| 力的主要来源 | 弹性恢复、扣合接触、摩擦 | 切削/犁削/摩擦、刀具与夹具接触、惯性 |
| 可逆性 | 正常使用主要可逆；损坏后不可逆 | 去除通常不可逆，重新插值位置不会恢复材料 |
| 首要验证 | 不按不能无损拔出；按对可拔；松手可回弹 | 去除体积正确；孔真的可通过；载荷随工况变化 |

“卡扣会变形”不意味着整个插头都要用高分辨率软体网格。大部分壳体可以近似刚体，把计算集中在弹片、扣齿和接触区。反过来，“钢板很硬”也不意味着加工能完全由刚体接触解决：切削局部发生不可逆变化，剩余工件则可以在首版中近似为固定刚体。

这里需要区分材料、结构和工艺三个概念。材料描述受力后的响应；结构描述材料如何形成弹片、钩子和支撑；工艺描述刀具如何从工件中移除材料。同一种塑料可以做不同锁止机构，同一种钢材用铣刀和砂轮加工也需要不同过程模型。

## 4. 调研得到的引擎能力边界

### 4.1 MuJoCo 不只有刚体，但原生 Flex 也不是通用加工引擎

MuJoCo 3.8.1 的官方模型文档包含 1D、2D、3D Flex，分别以线段、三角形和四面体组织变形单元；Flex 参与接触、约束和被动力计算，连续体模型允许定义弹性参数。因此，卡扣弹性结构可以先在当前引擎内尝试，不需要因为“会变形”就立即迁移平台。[^1]

需要特别警惕普通 mesh 的碰撞表示：MuJoCo 常规凸碰撞路径不是任意凹三角网格的精确碰撞。普通网格上显示一个孔，不保证碰撞中也存在这个孔。凸分解、合适的 Flex 表示、SDF 或定制碰撞路径各有条件，必须针对选定版本和形状验证。[^2]

3.8.1 同时提供 `mjSpec` 模型编辑和 `mj_recompile`，允许在保留仿真状态的同时重新编译模型。这说明拓扑变化不是绝对不可能，但它不是现成的实时铣削模块；编译耗时、句柄重解析、外部状态映射和接触一致性仍是 IBERO 的工程责任。[^3]

### 4.2 其他候选工具能解决什么，不能据此承诺什么

| 候选技术 | 原始资料确认的能力 | 对 IBERO 的建议与限制 |
| --- | --- | --- |
| MuJoCo 3.8.1 | 刚体机器人、接触、Flex、模型编辑 | 继续作为主引擎；先验证卡扣与局部可变碰撞，不承诺直接获得金属切削 |
| SOFA / SofaCarving | 插件能够按工具接触移除四面体，文档面向组织破坏 | 可作为软体及拓扑修改研究参考；删除四面体不等于钢材切削的塑性、热和切屑预测[^4] |
| PhysX 5.7 / ovphysx | FEM 可变形对象与 GPU 实现；具体接入层存在约束 | 有软体能力，但迁移并不会自动补齐加工模型；还要核对力读取、摩擦和拓扑接口[^5][^6] |
| Newton SolverVBD | 粒子、刚体及耦合求解 | 值得关注；所查 API 明确标注 Experimental，不应在本轮成为未经验证的必选依赖[^7] |
| COMSOL | 弹性卡扣接触示例，以及带塑性、摩擦和大位移的卡扣分析 | 适合离线分析力—位移和失效；示例不是具体网线连接器的已标定模型[^8][^9] |
| Abaqus | 金属塑性、应变率/温度依赖、损伤演化、失效单元删除 | 适合高保真局部参考；模型参数、网格和计算成本仍需验证[^10][^11] |
| pybullet_industrial | 铣削工具示例结合射线、过程力模型与物体移除 | 值得借鉴职责拆分，不能直接视为连续钢板切削的真值实现[^12] |
| CAMotics | 三轴 G-code 的几何加工结果可视化 | 可参考刀具轨迹与去除形状；其官网亦列出刀杆/夹具碰撞等限制，不宜替代机器人接触闭环[^13] |
| DiSECt | FEM、SDF 接触和连续损伤模型用于软材料切割 | 说明切割可以有物理依据且可标定；论文对象是软材料，不是钢材高速铣削[^14] |

PhysX 版本边界值得单独说明。5.7 概览提到部分 surface/attachment 功能仍处于开发中，而较新的 ovphysx 文档描述了自己的实现和限制，不能混在一起当作某个 Isaac Sim 版本的全部能力。所查 ovphysx 页面更新于 2026-08-21，明确列出静止形状拓扑、碰撞器等限制。另一方面，PhysX 5.1.2 的原始文档已经讨论了切割导致拓扑变化时必须更新预计算数据；因此，“PhysX 永远不能切割”同样不是准确结论。[^5][^6][^15]

综合判断：目前没有足够证据说明“换成某一个新引擎”比“保留机器人主引擎、补齐具体工业机制”更适合本项目。跨引擎耦合还会新增时间同步、接触力交换、坐标系和回放问题，应由明确的精度瓶颈触发，而不是先做一个万能引擎接口。

## 5. 卡扣：应该怎样定义真实的按压解锁

### 5.1 先把连接器拆成具有因果关系的部件

首个对象建议采用“具有以太网插头式按压舌片的参数化连接器”，而不是一开始声称完整复现某个 RJ45 产品的机械、电气和制造特性。

模型至少包含插头壳体、舌片固定根部、可弯曲舌片、扣齿、插座肩部及导向接触面。壳体与插座可先近似刚体，舌片承担主要弹性变形；按压工具必须接触舌片的真实表面。

核心闭环是：

```text
按压工具接触舌片
    → 接触力使舌片弯曲
    → 扣齿相对插座肩部的位置改变
    → 退出方向上的几何阻挡消失
    → 拉力克服剩余摩擦，插头退出
    → 舌片卸载回弹；若过载，则记录损伤或残余变形
```

Covestro 的卡扣设计指南把悬臂结构的变形、倒扣、允许应变、装配力和摩擦关联起来；COMSOL 则分别给出弹性接触和弹塑性卡扣分析。这些资料支持“结构＋材料＋接触”的建模路径，不支持把解锁简化成与物理状态无关的按钮事件。[^16][^8][^9]

“不按就拔不出来”应解释为：在规定姿态、正常载荷和无损操作范围内，扣合阻挡退出。足够大的外力可能导致破坏；这时即使插头脱离，也不能判定为正常拆卸成功。如果首版没有断裂能力，超过适用载荷后应报告超限并终止有效性判断，不能模拟成永远不可破坏的真实塑料。

### 5.2 推荐先做弹性降阶结构，而不是立刻求解整个插头

降阶的意思是保留决定任务成败的变形自由度，用较少的变量描述它。例如用少量被动弯曲关节连接短梁，或使用适合的梁/弹性离散模型，表达舌片在接触作用下的形状变化。

对理想、等截面、细长悬臂梁，在小变形、线弹性、自由端横向载荷条件下，可以用下式作为量纲检查与初始估算：

```text
I = b·t³ / 12
k_tip = 3·E·I / L³
F_tip ≈ k_tip·δ
```

其中 `E` 为弹性模量，`b/t/L` 分别为宽、厚、长，`δ` 为端部位移。实际舌片可能变截面、带根部圆角，按压点也未必位于端部；大变形、接触和塑性进一步改变响应。因此不能把这个估算直接当成真实连接器的完整力律。其用途是发现数量级错误，并指导后续拟合，而非替代标定。[^16]

建议的模型层级为：

| 层级 | 能做什么 | 应当如何标识 |
| --- | --- | --- |
| 逻辑占位 | 预设按压量达到阈值后解锁 | 仅调试任务流程，不作为工业物理验收版本 |
| 弹性降阶＋真实扣合接触 | 多位置按压、回弹、保持力、释放和复锁 | 推荐首个可交付模型；明确标定范围，不输出未经支持的实体应力 |
| 3D Flex / FEM | 更丰富的局部形变及连续体响应 | 与降阶模型在相同台架上比较，精度收益达到要求才升级默认模型 |
| 弹塑性/断裂扩展 | 永久变形、损坏后失去锁止等 | 需要额外材料和破坏数据，不能只增加一个布尔字段便宣称已完成 |

降阶模型的关节必须是被动力学元件，不能由任务脚本直接指定角度，做出“看起来弯了”的动画。单一转轴可以作为最初台架，但不能据此声称准确模拟了任意接触位置、扭转或局部压痕。

### 5.3 状态机应当观察机械状态，不应让任务阶段制造物理结果

可以记录 `locked`、`clearance_open`、`withdrawing`、`released`、`overload`，但这些标签应由实际几何和力学状态推导。

例如，`clearance_open` 不应只检查“按压量超过某个数”，还要检查扣齿相对肩部的净空、连接器姿态与退出路径。提前松手时，若扣齿仍处于肩部覆盖范围内，舌片回弹应重新产生阻挡；已经完全退出后，回弹不应把插头吸回插座。

不建议以“按压成功→关闭 weld→任务进入下一阶段”作为默认实现。若未来因效率采用解析锁止约束，它也必须是独立、可标定的机械模型，约束激活依据当前几何，能够响应反向动作和扰动，而非依赖任务状态机指令。

解锁也不等于摩擦为零。插头导向面、接触片等阻力是否建模，应明确声明；不能把所有拔出阻力都归因于舌片。

### 5.4 先解决工具能否真正完成动作

现有两指夹爪不能被默认认为能够一边牢固夹住插头、一边独立按压狭小舌片。第一个双臂任务建议把插座固定在台架上：一臂使用按压头，另一臂夹持插头并受控拔出。这样可以验证双臂动作协调，又不会引入不存在的第三个独立执行能力。

之后再扩展“一臂持插座、另一臂拆插头”。这需要组合夹持/按压工具、被动辅助夹具或合适的多指手，并由机械师配置真实安装关系、碰撞几何和执行通道。不是简单换一张夹爪模型图片。

## 6. 铣削：孔洞、切屑与加工力应分开建模

### 6.1 推荐的四层模型

第一层是剩余材料表示，回答“工件现在哪些地方还有材料”。第二层是刀具和加工过程，回答“当前运动能移除哪些材料”。第三层是力和扭矩反馈，回答“加工怎样影响机器人与工件”。第四层是切屑与表面显示，回答“如何展示已经发生的加工”。

这四层必须关联，但不能互相冒充。喷出粒子不证明发生了材料去除；材料减少也不证明切削力正确；曲线上的加工力不证明它真的作用到了机器人动力学。

### 6.2 材料去除采用几何法，是否就是“假的”

不是。对于主要评估机器人轨迹、接触载荷和成形结果的任务，可以用刀具有效切削区域的扫掠体，计算剩余材料。拟议关系是：

```text
候选去除 = 当前剩余材料 ∩ 有效刀刃运动的扫掠体
实际去除 = 加工模型在当前转速、进给、载荷和能力范围内允许的部分
下一步剩余材料 = 当前剩余材料 − 实际去除
```

这里的“允许”不是任务阶段开关，而是有明确适用范围的过程模型。未启动的铣刀、刀柄、夹具、工具背面，不能只要接触就把工件擦掉。超出模型支持范围时，应阻挡、过载失败或报告模型无效；不能不受功率限制地持续删除材料。

pybullet_industrial 的示例源代码采用射线获取啮合信息，计算过程力，然后移除命中的物体。这证明几何去除和过程力可以分离实现，也暴露了边界：若钢板是单一刚体，删除命中物体不是局部铣孔；需要更细的材料表示。该示例不是可直接照搬的工业精度保证。[^12]

### 6.3 剩余材料怎么存储

| 表示方式 | 直观解释 | 适合的第一步 | 主要代价或限制 |
| --- | --- | --- | --- |
| 规则体素 | 三维小格子记录材料是否存在 | 小工件、孔槽、原型验证、体积记账 | 分辨率提高时内存和碰撞成本快速增长，表面可能台阶化 |
| Dexel | 沿一组采样射线记录一段或多段实心区间 | 工具轴方向受限的三轴加工 | 方向相关；多方向与复杂倒扣需更复杂表示，不等于普通单值高度图 |
| 稀疏体素 / SDF | 局部存储材料或到表面的带符号距离 | 更复杂形状与局部更新 | 表面重建、距离更新和碰撞接入需要额外工程验证 |
| 边界网格布尔 | 直接更新工件表面三角形或实体边界 | 离线结果、低频更新 | 连续布尔、薄片和退化面处理可能成为稳定性瓶颈 |
| FEM 拓扑修改 | 在力学网格上表达损伤和分离 | 高保真局部研究 | 参数、求解、重网格及机器人耦合成本更高 |

建议第一步用小范围体素验证闭环，因为占据状态、体积、孔洞和回放都容易检查；通过后再根据实测瓶颈决定是否转向 Dexel 或稀疏表示。这里的顺序是工程判断，不是关于哪一种表示普遍最优的结论。

普通高度图只表达每个平面位置上的一个高度，不能泛化到任意内部空腔和悬垂结构。也不建议把整块钢板分成海量独立动态小刚体：首版工件固定，材料采样单元不需要各自获得六自由度。

### 6.4 力不是“碰到就给一个常数”

首版推荐采用经过标定的机械式/经验切削力模型，并声明刀具、材料牌号和工况范围。载荷至少应随有效啮合、切深、每齿进给和材料参数改变，而非依赖目标轨迹的完成百分比。

Sandvik Coromant 的铣削资料明确联系了进给、转速、每齿进给、材料去除率、比切削力、功率和扭矩。这些关系适合用于参数定义和量纲检查，但还不足以直接生成任意方向上的瞬时六维接触载荷。[^17]

以统一 SI 单位表达，基础检查可以写为：

```text
f_z = v_feed / (n_rev_per_s · z)
Q = 实际去除体积 / Δt
平均切削功率估计 P_cut ≈ k_c · Q
平均主轴切削扭矩估计 τ_cut ≈ P_cut / |ω|
```

其中 `k_c` 取 Pa，`Q` 取 m³/s，得到 W；`ω` 取 rad/s。它们是给定条件下的平均量估计，不能用 `P/v` 在零进给时随意除零，也不能据平均功率唯一恢复三维力方向。完整过程模型还需要局部刀齿方向、啮合角、切屑厚度及切向/径向等系数。

主轴停转时应进入未切削接触状态，不能为了避免除零偷偷保留去除行为。刀具原地旋转在初始啮合或下压过程中可能仍有去除，不能简单规定“没有平移就永远没有切削”；但已经完全清空且没有新的接触时，不应凭时间继续扣除体积或产生恒定切削力。摩擦、擦碰与切削需要分别处理。

对于高转速铣削，第一版可以明确采用旋转平均的几何和载荷，而不是假装机器人仿真时间步能解析每个刀齿的高频冲击。若后续研究颤振、齿间载荷或表面微观纹理，需要增加过程子步和相应动力学，不能只提高渲染帧率。

### 6.5 力必须进入动力学，且不应被重复计算

过程模型输出应包括作用位置、力、力矩和坐标系。机器人受到刀具载荷，工件受到相应的反作用；固定工件的反作用由夹具/世界约束承担，仍应能审计。力矩换算需要包含作用点偏移产生的 `r × F`，不能把两个不同原点上的六维数值直接取反。

加工接触与 MuJoCo 刚体接触必须明确分工。若有效刀刃的材料穿入已由切削模型解释，就不能同时再用不可穿透的完整刀具体积把相同部分顶出，造成载荷重复。但也不能关闭刀具与整个世界的所有碰撞：刀柄撞夹具、停转工具撞板、未加工面擦碰都应保留。

外加工艺力不是天然会出现在每一种接触传感器查询里。必须分别核对：动力学实际施力、腕部传感器输出、审计真值，以及观察空间提供的测量值。不能为了让读数好看，把同一加工力在多个通道重复相加。

### 6.6 切屑应该做到什么程度

建议分三级交付：

- 几何级：留下正确孔槽，记录去除体积和质量，没有逐屑动力学。
- 展示级：按去除位置和数量级生成切屑粒子，明确是视觉或粗粒化代理，不用于推断真实切屑温度、形状和危险轨迹。
- 物理研究级：求解塑性流动、损伤、热和切屑分离，并验证其预测能力。

第一版应优先完成几何级和受控的展示级。若切下一块完整余料，这块余料不能伪装成几个消失的视觉粒子：它涉及连通域分离、质量和惯量，以及是否成为新的动态物体。首版可以把这种工况明确排除，后续再实现。

### 6.7 如果坚持真实计算钢材切屑，会多出哪些问题

Abaqus 的 Johnson–Cook 文档说明了应变硬化、应变率与温度项；损伤文档则明确讨论了失效后的刚度退化、单元删除和网格依赖。这说明“更真实”也不是零假设：仍然需要本构模型、损伤规律、参数和数值正则化。[^10][^11]

若目标是预测钢材切屑形态、温升和局部应力，还需定义刀具刃口及摩擦、材料热学参数、加工边界条件，并选择适合大变形和分离的离散方法，例如相应的 FEM、ALE/CEL 或粒子法研究路线。本文不据此认定其中某种方法已在 IBERO 验证，更不承诺其能够直接实时驱动完整机器人。

DiSECt 的研究提供了“FEM＋接触＋损伤＋参数识别”的有价值范例，但研究对象是软材料切割。它不能作为把钢材换个弹性模量就能进行高速铣削的证据。[^14]

因此建议采用两层保真路线：在线模型服务机器人操作和成形结果；离线模型或实测数据提供载荷曲线、参数和误差边界。有限元参考本身也需要实验校核，不能自动称为现实真值。

### 6.8 电动切割钢板怎样复用，又有哪些不能复用

“切割电机”描述的是驱动装置，不足以确定加工模型。带齿锯片与磨料切割片都可能由电机旋转驱动，但其有效加工区域和载荷规律不同。后续配置必须明确工具类型，不能只提供一张圆盘 mesh。

对于带齿锯片，拟议的过程级方案是记录外缘切齿运动、有效切缝宽度、啮合与进给，用对应材料—刀具的力模型限制去除。对于磨料切割片，第一版可使用经标定的平均去除率与力/功率模型，但不能直接复用端铣刀的每齿切屑模型；磨耗、热影响和火花若未建模，应明确排除。

两者都可以复用剩余材料存储、扫掠更新、孔槽碰撞、反作用及回放；需要分别实现工具有效区和工艺参数。切割片的厚度、安装姿态与运动共同影响切缝，刀盘非有效区域和防护结构仍需保留碰撞。

切穿钢板形成两个宏观零件时，还要检查材料连通性，并区分“仍被夹具固定的两块材料”与“已经自由掉落的余料”。建议切割能力分两步验收：先做不完全切断的真实切缝，再做带分离块状态和动力学的完整切断。完整切断不能被一个 `cut_complete` 标签替代。

材料记账也应独立于切屑粒子数量：在密度不变、未建模热膨胀的首版假设下，以 `去除质量 = 密度 × 去除体积` 记录物质转移；剩余工件、分离余料和切屑/未显式模拟的碎屑储量应有一致账目。少量展示粒子可以代表大量细屑，但不能同时把它们计作额外生成的材料。这个账目保证的是所声明模型内的质量一致性，不是对每片真实切屑运动的预测。

## 7. 加工在 MuJoCo 中最先需要通过的工程关卡

最大风险不在切屑动画，而在**变化后的材料边界怎样成为真正参与接触的碰撞边界**。

首个验证实验不需要 G1。只放置一个固定工件和探针：初始探针被工件阻挡；移除指定孔槽后，合适直径的探针可以通过；移到未切区域仍被阻挡；复位后重新阻挡。这个小实验同时检查材料表示、碰撞更新和复位。

候选实现包括预分配的局部碰撞代理、基于 `mjSpec` 的受控重编译，以及针对剩余材料的专用碰撞表示。第一种要检查几何修改后包围结构、碰撞过滤和已有接触的有效性；第二种要检查性能和状态映射；第三种要检查算法及版本支持。修改透明度只影响外观，不能作为碰撞更新方案。[^2][^3]

这里暂不指定一个未经测试的“每帧修改 geom 就行”的实现。应先在固定版本完成最小验证，再选择生产路径。若只能做到低频重编译，应明确其暂停或同步语义，不以连续播放掩盖物理计算中的跳变。

几何更新还应形成一致性边界：本步使用哪一版剩余材料计算力，哪一版用于接触和显示，必须定义清楚。加工子步提交几何变化时，应同步更新相关查询；不能让任务判定看到新孔、碰撞仍看到旧钢板。

## 8. 对 Core 的最小架构调整：材料、机构、加工过程分责

不建议立即设计庞大的通用仿真器接口。应该由两个独立台架和已有线束共同逼出最小结构，再逐步替换当前线束专用连接点。

拟议组成关系如下，名称用于表达职责，不是现有 API：

```text
scene_config.yaml
    ├─ 材料与几何：塑料舌片 / 线束 / 钢板
    ├─ 机构：扣齿、肩部、固定根部、装配关系
    ├─ 工具与过程：按压头 / 铣刀、主轴和加工模型
    └─ 数值配置：离散分辨率、求解步长、接触精度
             ↓
        SceneCompiler
             ↓
    MuJoCo 机器人与接触 + 材料/机构/加工运行状态
             ├─ 材料恢复力与工艺力 → 统一施力 → 动力学
             ├─ 剩余材料变化 → 碰撞与显示更新
             └─ 测量与真值 → 审计 / 回放 / task_spec.py
```

### 8.1 四个最值得形成的职责边界

材料模块负责物性、材料内部状态、恢复力与损伤定义。卡扣模块负责弹片及配合面的结构关系、净空和锁止状态。加工模块负责工具有效区域、过程模型和材料去除。Core 负责它们与机器人、接触、状态和观测之间的协调。

“机构”不应只是任务里的一个阶段枚举；“加工”也不应只是某个场景函数里执行几何删除。否则后续每个场景都要复制一套物理逻辑，P4 菜谱作者实际上变成了求解器作者。

### 8.2 场景配置应该保存哪些信息

| 对象 | 场景可定义的内容 | 必须明确的边界 |
| --- | --- | --- |
| 弹性卡扣 | 舌片长宽厚、根部/扣齿/肩部几何、按压区域、物性或标定曲线、摩擦、允许变形和载荷 | 报警阈值不等于破坏本构；尺寸改变后旧标定不一定有效 |
| 可加工工件 | 初始形状、材料牌号、密度、固定方式、离散分辨率、参数来源 | 不能只写 `material: steel` 就声称有钢材切削精度 |
| 加工工具 | 刀具类型、有效刃区、刀柄碰撞、刀径、齿数、主轴转速/扭矩能力、进给范围 | 铣刀、锯片、砂轮不能共享一个未经区分的通用切削常数 |
| 加工模型 | 系数及单位、适用材料/刀具/速度范围、标定版本、超范围处理 | 未标定结果应显示为示例/待标定，不给出虚假工业认证 |
| 数值实现 | 梁段数或网格分辨率、接触容差、子步、几何提交频率 | 与真实物性分开；不能通过调数值软化偷偷改变材料定义 |

配置仍然面向 P4 可读、可改，但不能所有字段都自由组合。校验器应拒绝矛盾配置，如选择不支持塑性的模型却要求塑性残余量，选择不支持倒扣的几何表示却声明任意内腔加工。

### 8.3 任务作者与材料专家如何协作

P3 材料专家交付的不应只有一个网格，而应包括模型适用范围、参数、参考曲线、验证台架和误差报告。机构建模需要 P3 与 P2 共同确认扣合几何及装配关系；P2 还需负责工具安装、按压可达性和执行器能力。

P4 菜谱作者负责选择这些模型、配置工况、指定目标及判定结果。例如要求无损拔出，或者要求某个孔的尺寸和贯通性。不应在 `task_spec.py` 中把卡扣强制解锁，或把目标孔区域直接删除。

数值上还要明确外加力的汇总责任。现有 `CableMechanics.apply()` 面向自己的节点写入外加广义力；增加多种材料和加工载荷后，必须有明确的清零、累加和施力顺序，避免一个模块覆盖另一个模块，或把上一子步的力重复保留。

### 8.4 材料状态必须进入复位、审计和回放

现有 `Trace` 保存 `mjSTATE_INTEGRATION`，适合当前固定模型的审阅回放。材料去除后，还需要保存或可确定地重建剩余材料、加工工具状态、损伤历史、模型变更事件和相关版本。若模型大小改变，原来的固定长度状态数组也不能未经处理直接复用。

推荐先做“初始材料＋有序去除事件＋周期性材料快照”，再评估压缩和性能。回看加工前一帧时，孔必须恢复到当时的大小；再次 reset 时应恢复未加工工件。纯审阅回放与可继续积分的完整 checkpoint 继续区分，不能借扩展回放之名默认获得策略状态恢复能力。

如果以后工件自由运动或整块余料分离，还必须一致地处理质量、质心、惯量和动量。首版把工件固定不是逃避这个问题，而是明确限制任务范围，并把它留作后续独立关卡。

## 9. 验收：什么证据能够说明不是按脚本演戏

验收应从受控台架开始，保留失败动作和反事实测试。一次演示成功不足以证明模型正确。

### 9.1 卡扣台架与双臂任务

| 测试 | 应看到的结果 | 能排除的问题 |
| --- | --- | --- |
| 自由舌片按压—卸载 | 力—位移与参考一致，弹性范围内回弹 | 动画弯曲、无恢复力、错误刚度 |
| 正常范围内不按直接拉 | 仍被扣齿阻挡，不判无损成功 | 仅靠摩擦假装卡扣、过软接触穿透 |
| 按压不足或位置偏移 | 依几何与变形决定是否仍锁止 | 任意触碰按钮就解锁 |
| 正确按压并拉出 | 净空出现，退出，卸载恢复 | 状态标签与实际运动脱节 |
| 未脱离时提前松手 | 根据剩余几何重叠重新锁止或受阻 | 单向任务状态机、永久关闭约束 |
| 过载或过弯 | 明确超限；仅在有支持时模拟损伤 | 把破坏性拔出算成功 |
| 改厚度、扣齿高度、摩擦 | 结果按模型预期改变，必要时重新标定 | 参数只改外观、不改动力学 |
| 步长与结构离散加密 | 关键力和释放位置趋于稳定 | 结果由数值设置主导 |

指标包括按压力峰值、按压曲线、释放行程、保持力、接触穿透、回弹误差及操作成功率。容差需要相对实际倒扣和装配间隙制定：不能在需要分辨微小扣合间隙的任务里，接受同量级的数值穿透。原始方案里的微间隙目标不能只靠模型单位写成毫米来宣称达到。

### 9.2 加工台架与机器人任务

| 测试 | 应看到的结果 | 能排除的问题 |
| --- | --- | --- |
| 停转刀具压向工件 | 不发生已定义铣削去除，保留接触或超限处理 | 接触即橡皮擦 |
| 同一轨迹重复切空槽 | 无新增材料时去除量为零，载荷按接触状态变化 | 每帧固定扣体积、固定加工力 |
| 刀柄碰工件/夹具 | 保留碰撞，不当作有效切刃 | 全局关闭碰撞 |
| 直槽/通孔解析体积对比 | 在离散误差范围内一致 | 几何漏切、步长跳跃、多计去除 |
| 加工后独立探针通过孔 | 孔内能通过，邻近未切处受阻 | 视觉孔洞与碰撞不一致 |
| 不同材料、切深和进给 | 在标定范围内呈现合理载荷差异 | 仅播放预设力曲线 |
| 功率/扭矩能力超限 | 有定义的降载、停滞或失败处理 | 无限加工能力 |
| 工具—工件力与力矩审计 | 坐标换算正确，反作用及约束反力可解释 | 单边施力、重复施力 |
| 复位及前后回放 | 材料历史、孔槽、显示和碰撞一致 | 只恢复机器人位置 |
| 分辨率/步长收敛与性能 | 记录误差及运行成本，不隐藏代价 | 用粗糙几何换取虚假的实时高保真 |

未做热力耦合时，功率与去除量审计只能支持过程级一致性，不能据此声称已经验证了全部能量转化、温升或切屑物理。

## 10. 推荐开发顺序与阶段门槛

以下是建议顺序，不是已经开始的 coding 清单。每个阶段先通过自己的可执行检查，再接入更复杂任务。

### 第一步：收紧材料声明，建立共同台架记录

保留现有线束测试，整理参数单位、物性与数值参数的区别，建立参考曲线、版本和适用范围的记录方式。同步定义“报警”“损伤”“断裂”“去除”各自意味着什么，避免不同场景使用同名指标却表达不同能力。

交付条件：现有线束功能不退化；新材料不能以缺少关键参数的配置冒充已标定模型。不需要先开发 LeRobot、策略训练或大规模插件系统。

### 第二步：做无机器人的卡扣机械台架

创建参数化舌片、扣齿和插座，完成被动弹性与真实接触。对降阶方案和必要的 Flex 候选做同工况比较，完成不按、轻按、正确按压、提前松手与过载测试。

交付条件：机械行为由接触和结构产生；有量化曲线、离散收敛检查及明确误差，不能只交付解锁动画。

### 第三步：做双臂卡扣任务链

先固定插座，一臂按压、一臂拔出；通过后连接现有线束和端头操作，形成“接近→接触识别→按压→保持→受控拔出→交接/放置”的链条。后续再扩展重新插入和锁止检查。

交付条件：正确动作成功，错误顺序和扰动导致符合机械机制的失败；更换合法几何参数后仍能运行，不依赖单一轨迹下的隐藏解锁条件。

### 第四步：做材料去除与碰撞一致性的最小实验

不接机器人、不喷切屑，只验证固定工件、局部去除、独立探针碰撞、reset 和几何回放。比较碰撞代理和受控重编译的代价，决定首版可变几何的实现路线。

交付条件：洞在视觉、占据状态与实际碰撞中一致；有性能测量。若这一步不过关，暂停扩大铣削场景，不能用漂亮画面绕过架构问题。

### 第五步：补齐固定钢制工件的铣削过程闭环

先定义一个具体材料牌号和一种端铣刀，采用受限三轴工况，完成直槽、浅腔及可行入刀方式下的通孔。选定的刀具若不支持中心下切，就不能使用穿心直插的假动作，应使用合适的侧向进入、斜坡或螺旋路径。

加入实际去除量、过程力、主轴扭矩/功率限制和反作用审计，再接机器人。钢板仍是目标对象；数据不足时可以做“钢材参数待标定”的工程示例，但不能把未验证系数包装成真实钢材加工性能，也不能暗中替换成软材料后宣称需求完成。

当前 G1 场景没有证明其适合某种钢材切削负载。加工能力应先在工具台架核定，再核对机器人、夹持、主轴和夹具的载荷范围；机器人构型不适用时明确换用合适配置，而不是降低工件力学响应来强行演示成功。

交付条件：几何、动力学载荷和能力限制构成闭环，测试覆盖空切、停转、过载和未切区域碰撞。没有实测标定前，交付名称应为过程级仿真原型。

### 第六步：形成可复用 Core，并判断是否进入 0.2

在已有线束、卡扣、加工三个真实使用者基础上，整理场景编译、材料/机构/工艺状态、统一施力、审计与材料回放。此时抽象边界来自已验证需求，不需要预先设计与当前工作无关的外部接口。

建议进入 0.2 的条件是：至少一个弹性解锁任务和一个材料去除任务通过量化门槛；错误动作有可信的物理后果；材料参数确实影响结果；场景可以组合已有机制；版本、参数、几何变化和回放可追溯。完整金属热切屑、任意五轴加工、磨削、自由余料动力学和塑性破坏可以继续作为后续独立能力，不以一个版本全部承诺。

## 11. 现在最值得准备的资料

优先准备实际对象和力学数据，而不是同时安装多套大型引擎。原型可从参数化几何和公开资料开始，但可信的工业参数最终需要具体对象的数据支持。

| 方向 | 最有价值的资料 | 暂缺时的处理 |
| --- | --- | --- |
| 卡扣几何 | 插头/插座 STEP 或带尺寸剖面图，舌片根部、扣齿、肩部、间隙及可接近区域 | 使用明确标识的参数化示例，不冒称某产品复刻 |
| 卡扣材料与响应 | 具体聚合物/牌号，按压—位移曲线，卸载曲线，正常保持力，允许变形 | 先做模型一致性验证，力值标为待标定 |
| 夹持与按压工具 | 安装尺寸、可达行程、夹持/按压独立自由度、力限制 | 首版使用固定插座与独立按压工具 |
| 钢材及刀具 | 钢材牌号、板厚、刀具型号/刀径/齿数/刃长、刀柄几何和允许工况 | 不用一个泛化的“钢材常数”代替完整配置 |
| 加工数据 | 对应转速、进给、切深下的力、主轴负载、去除体积或加工结果 | 先采用注明来源和适用范围的过程模型，后续用实测修正 |
| 设备信息 | 主轴扭矩—转速特性、机器人与夹具能力、计算机 CPU/GPU 配置 | 不承诺实时帧率和实际设备加工能力 |

不需要现在购买 COMSOL 或 Abaqus 才能启动。已有授权和专业人员可以用于离线参考；没有授权也可以先进行解析台架、MuJoCo 原型和公开参数研究。若需要开展真实钢材加工采样，应由具备条件的实验平台和人员执行，不能把仿真中通过当作真实加工安全依据。

## 12. 最终建议

最优先交付的是“确实需要按压变形才能无损拔出”的卡扣，而不是更多抓取场景；第二个关键交付是“孔真实存在、载荷确实反作用于工具”的固定工件加工，而不是飞屑动画。

保留 MuJoCo 主引擎，先用可标定的模型解决操作层面的真实因果；把高精度 FEM 作为验证和升级手段。让规则表达明确的工艺和失效模型，让任务只评价结果，不让任务脚本制造结果。

由此形成的核心优势应当是：同一条动作，在材料、几何或工况改变后，会产生可解释、可测量、可验证的不同结果。这比场景数量或引擎名称更能体现 IBERO 的工业价值。

### 13.2 本轮承诺的能力与明确不承诺的能力

主线交付包括：参数化弹性卡扣台架；双臂按压拔出；线束与卡扣组合任务；固定工件材料去除；三轴受限端铣过程；实际碰撞与加工力反馈；材料历史回放；持续可审阅的可视化和自动化验收。

卡扣首版是可恢复弹性模型，超出范围报告过载，不默认包含物理断裂。加工首版是过程级模型，工件固定；钢材牌号、刀具与参数来源必须可追溯，数据不足则显式标为 provisional。不得以减少材料真实响应、隐藏载荷、提高执行器能力或放宽目标容差让演示强行成功。

本轮不自动包含：购买商业软件、真实机器人/主轴控制、真实切削实验、全平台迁移引擎、LeRobot/ROS 2 接口、策略训练、任意五轴加工、热切屑预测、磨削完整模型、自由余料动力学，以及无关目录的重构。

对于机器人加工：先验证现有构型及工具是否满足所选仿真工况。若通过载荷/可达性检查，在现有机器人上完成演示；若不满足，交付通过验证的加工台架及不适配证据，机器人加工任务保持未完成并请求选择构型，不能把台架冒充完整机器人交付。

### 13.3 两条独立的验收状态

后续每项材料能力同时标记两种状态：

| 维度 | 状态含义 | 可以据此声明什么 |
| --- | --- | --- |
| 工程实现 | 未开始 / 进行中 / 已实现待验收 / 通过 / 阻塞 | 方程、几何、接触、状态、复位及测试是否按定义实现 |
| 物理标定 | 示例参数 / 解析验证 / 数值参考验证 / 实测标定 | 预测与哪一类独立参考一致，以及适用工况是什么 |

## 14. 主线量化验收与反作弊门槛

### 14.1 门槛身份：工程目标，不是行业标准或已达结果

本节数值是为连续开发提出的**首版工程验收目标**，不是文献承诺、行业认证或当前测量结果。审阅通过后在 S0-06 固定为版本化测试配置；需要改动时记录原因、旧值、新值和对比，不允许测试失败后静默放宽。

相对误差的分母需预设非零参考尺度；参考量接近零时改用已声明的绝对容差。曲线误差应记录完整曲线，并在相同物理坐标上比较，不能随意对齐峰值抹去释放位置误差。

纯数学/几何单测、物理积分台架、机器人任务和真实材料标定分别统计，不能用某一层通过推断其他层已经通过。

### 14.2 各阶段必须保留的证据

| 门槛 | 强制检查与拟议标准 | 证据和不通过时的处理 |
| --- | --- | --- |
| G0 | 当前 pytest、场景校验与基线全部实际执行；现有失败原因和分母完整 | 版本/配置/源码摘要＋原始日志；环境或旧基线异常先定位，不归咎于未开始的新功能 |
| G1 | 两个旧场景配置仍通过；新场景非法字段/NaN/Inf/能力冲突均拒绝；力叠加测试通过 | schema 与施力单测；禁止通过宽松读取任意字段绕过校验 |
| G2 | 独立台架能够演示按压—变形—净空—退出；正常载荷下不按受阻；卸载恢复 | 原始力、位移、净空、接触和状态时间序列，不仅截图 |
| G3 | 理想梁小变形刚度误差 ≤5%；两次最细离散/最小步长对关键峰值力及释放行程的相对变化 ≤5%；弹性卸载残余位移 ≤峰值位移的 2% | 仅适用于声明的准静态/充分松弛工况；解析适用假设要同时满足；默认卡扣物理测试不得有非有限值或数值恢复 |
| G4 | `latch_release` 默认 seed 0–19 至少 18/20 无损成功；`harness_unplug` 同样至少 18/20；规定错误动作集不得出现假成功 | 按场景分别计数，不能合并分母；每个失败有终态和原因；任务不能关闭锁止或直接移动对象 |
| G5 | 同事件重复应用零新增去除；剩余体积单调不增；正常尺度的解析直槽/通孔体积误差 ≤5%；三档分辨率比较 | 小于网格尺度的特征明确为不支持，不靠此门槛声称任意精度；边界误差随加密收敛 |
| G6 | 孔内/孔外探针测试、复位、材料事件重放全部通过；占据/事件哈希一致；同版本数值状态往返满足预设绝对容差 | 不以视觉替代实际碰撞；碰撞与材料版本不一致立即判失败，不进入加工集成 |
| G7 | 停转、空切、刀柄碰撞和过载用例全部正确；合成参考的平均力/扭矩误差 ≤5%；准静态载荷传递误差 ≤5% | 合成参考必须独立计算且标识；不代表钢材实测精度；加工不能超能力继续无条件去除 |
| G8 | 直槽、浅腔、通孔各 10 个冻结种子至少 9/10 成功；成功需形状/体积合格、无禁止碰撞/超限和假孔；真实 GUI 交互检查通过 | 三种加工结果分别统计；机器人不适配不能用台架结果替代；GUI 未实际检查必须标“未验收” |
| G9 | 所有主线任务有状态和证据；新测试全通过；旧回归无未解释退化；所有未标定/不支持项已列出 | 整体报告、逐例数据、复现命令与失败清单；尚未通过的主线任务不从清单移除 |

G3 的接触精度另设几何尺度门槛：定义本测试中决定锁止的最小非零倒扣/净空尺度 `c_feature`，数值接触穿透峰值目标不超过 `0.1 × c_feature`。必须报告实际长度值；没有定义尺度、几何本身相交或尺度过小不可分辨时，不能只报告“误差 10%”。这是首版目标，不是自动达到了原方案全部微间隙要求。

G5/G6 的孔尺寸与碰撞代理误差按网格尺度检查：首版表面/边界偏差目标不超过 `2 × cell_size`；通孔探针与孔壁保留至少 `3 × cell_size` 的径向净空，避免把亚网格细节当作验收内容。未切实体阻挡测试必须单独进行，防止通过放大孔或禁用整个工件碰撞蒙混过关。

G7 的坐标变换与反作用单测独立于积分误差：使用非零力臂、旋转坐标和纯力矩用例，合成值采用明确的绝对容差，例如力 `1e-6 N`、力矩 `1e-6 N·m`。实际积分传感器的 5% 门槛针对稳态增量载荷、扣除已声明基线后的对比，不能把数学变换精度当作传感器动态精度。

### 14.3 测试矩阵怎样确定，避免只为一个 demo 调参

卡扣至少准备三组在模型有效范围内的配置：默认、改变舌片刚度/厚度、改变扣合几何。每组独立执行不按、按压不足、按偏、正确按压、提前释放及超限六类台架试验。预期净空关系在运行前记录，不能简单假设所有“按偏”都应失败；实际几何允许释放时应按几何解释。

机器人默认场景使用固定 seed 0–19；seed 实际影响哪些初始偏移、摩擦或扰动，在报告里保存解析后的值。不能把没有任何随机差异的 20 次重复运行说成 20 种泛化工况。至少两组合法变体各执行 5 个独立留出用例，目标每组至少 4/5 成功，不能只给整体平均数。

加工台架以三档分辨率执行直槽、浅腔、通孔；再增加停转、重复空切、工具偏移、过大进给、刀柄碰夹具、一次几何提交失败及重复 reset。大幅超出已声明加工范围的测试应验证拒绝/失败语义，而不是要求所有配置都能完成切削。

调参集和留出集在 S0/S1 建立；任何为调参重新使用的留出数据应改标为开发集，并新增未使用的验证工况。对模型不支持的区域给出边界，不把所有失败归类为“配置问题”后排除。

### 14.4 旧功能不得退化的具体含义

旧单元测试全部通过，旧场景加载、张力反馈和材料公式保持语义。固定 seed 0–19 的稳定保持目标保持 20/20；接触交接不低于历史契约 18/20；三组材料 × 三种子的张力验收保持 9/9。实际起始基线若与历史不同，在 S0 查明并单独说明，不悄悄选择较低目标作为新基线。

旧 GUI 仍能初始等待、Enter 重跑、结束不退出、暂停/单步和回放。新轨迹格式不能关闭现有场景/源码/资产/引擎版本校验。算法修复导致数值结果变化时，解释具体物理原因并重跑证据，不要求逐位复刻旧错误，也不能借修复名义回避成功率下降。

### 14.5 性能目标与测量口径

正确性是硬门槛，性能必须测量，不能未经试验承诺某个帧率。基准机的 CPU/GPU、线程设置、物理步长、工件大小、网格分辨率、碰撞代理数量和 viewer 开关全部记录。

分别测量建模耗时、无渲染物理速率、单次几何提交耗时分布、材料快照大小、回放速率，以及 GUI 输入响应。实时因子统一定义为 `仿真时间 / 墙钟时间`，不用加速播放视频的速度代替。

首版交互体验建议目标：默认小场景无渲染实时因子 ≥0.5；暂停后的 GUI 操作响应通常不超过 1 s。它们是待 S0 基准机固定后确认的体验目标，不替代 G2—G8 的物理门槛。未达到时必须报告并限制场景容量，给出定位结果；是否将特定性能数字提升为发布硬门槛，在开发前明确，不能事后挑选。

## 16. 连续工作规则、状态登记和异常处理

### 16.1 每项任务的完成循环

## 1. 这次最值得做什么

建议把下一阶段定位为 **“以 Core-0.1 为物理底座，建设可复用、可评价、可展示的工业任务；以双臂立式布线作为 Core-0.2 的主任务”**。

重点从“单个机制能否仿真”转向“机器人能否完成一件有明确要求的工业工作”。材料实测标定继续保留为独立状态，不作为开始任务开发的前提。新增底层工作只围绕布线所缺的能力展开。

本轮最重要的交付是：一段柔性线束放在可抓取的供料架上，双臂抓住裸线段，整理和适度张紧，逐个压入立式板上的弹性侧向卡扣，完成指定走线；机器人松手退开后，线束仍保持在正确位置。系统能解释成功或失败的原因，并提供可复现演示及网页视频。

推荐开发顺序：

1. 验证裸线抓持和单个弹性线夹，解决任务所必需的接触能力。
2. 完成双臂单卡扣任务，建立独立于控制脚本的成功判定。
3. 复用同一套组件，完成直线、L 形和开口矩形布线。
4. 把已有拔线束、铣削任务纳入共同的任务说明、结果报告和展示目录。
5. 让贡献者能够通过场景菜谱增加同类任务，形成可对外试用的 Tasks Preview。

“Core-0.2”是本计划的目标版本，不表示现在就将 `pyproject.toml` 改为 0.2。先形成可审阅候选版，完成验收后再决定版本发布和主分支合并。

## 3. 我们要做的布线场景

### 3.1 工位与动作

工位包含固定在地面/工作台上的立式板、若干朝向机器人开口的线夹、一段自由线束和一个真实供料架。首版保留现有固定基座 G1 双臂与可配置末端执行器，板面范围由双臂共同可达区域决定，不照搬整个人高机柜。

用户给出的图片用于参考“立式板上布线”的空间布局；它没有提供线夹剖面、尺寸或材料，不能据此声称复刻了某个商品。

以板面定义坐标：`u` 为水平，`v` 为向上，`n` 为朝向机器人。压入动作主要沿 `-n`，重力沿世界竖直向下。这里的“往下按”是压入夹口，不一定是沿重力方向下降。

典型操作过程：

1. 双臂从供料架抓住相距一定弧长的两个裸线段。
2. 调整两抓点间距，使待插入线段较稳定，张力处于允许范围。
3. 将两抓点之间的一段线对准线夹开口；通过两手协同的法向运动压入。
4. 线束撑开弹性夹口，越过唇边，夹口回弹；线束留在夹座内。
5. 释放或更换抓点，整理下一段；避免把已经固定的线段再次拔出。
6. 全部走线完成后，两手松开并退到检查区域，线束稳定保持。

允许一手稳定、一手逐步引导等不同策略；上面是参考控制器的流程，不强制所有策略执行相同动作顺序。

### 3.2 对“拉紧后更容易压进去”的建模解释

张力会改变线段在横向载荷下的响应，使其更容易定位、减少局部让位。这不意味着线材本身的弯曲刚度 `EI` 被临时提高。

本轮不添加“张紧成功后才允许插入”的物理开关，不在插入时吸附线束，不提高材料刚度来配合动画。线束能否压入，来自线材弯曲/拉伸、夹口形变、摩擦和机器人动作的共同作用。

“完全松弛一定压不进去”也不能作为普遍物理规律：支承位置、抓点距离、夹口形状都会影响结果。应在相同工况下比较松弛与适度张紧时的横向偏差、插入率、峰值载荷和滑移；不为展示预设想要的结论。过度张紧则可能导致超限或使已安装线段脱扣。

这也是本轮与只做路径动画的区别：任务层提出要求，物理层产生结果。

### 3.3 从小到大的任务阶梯

以下场景名为拟议名称。主线均为单根线束，不包含打结、线束交叉、分支束线或接线端连接。

| 层级 | 拟议场景 | 内容 | 交付身份 |
| --- | --- | --- | --- |
| B0 | `cable_clip_bench` | 单线夹、线段侧向压入、松开和拉脱台架 | 机制测试，不算机器人完成任务 |
| B1 | `cable_clip_insert` | 双臂抓裸线，张紧、压入一个线夹并松手 | 最小完整机器人任务 |
| B2 | `cable_route_straight` | 同板直线布线，默认 3 个线夹 | 首个多步骤布线任务 |
| B3 | `cable_route_l` | 默认 4 个线夹、一个有圆角的 90° 转向 | 转角与换抓任务 |
| B4 | `cable_route_rectangle` | 默认 6 个线夹、四边走向、三个圆角转向，首尾留开口 | 本轮完整展示任务 |

线夹数量是默认菜谱值，最终尺寸和间距在 R1 根据可达性与线长冻结。矩形是**沿矩形外形走线的开口路径**，不做首尾连接，不把线材折成零半径直角。

开发时可以使用“已预抓持”的辅助起点缩短调试，但它必须有单独标记；正式 B1–B4 从供料架取线开始。预抓持只允许通过真实接触建立，不能添加机器人—线束焊接约束。辅助起点结果不计入完整任务成功率。

- 关键函数、参数单位、模型假设、可选项和非直观实现处补充中文注释。

### 4.2 不随本计划自动展开

真实材料标定、真实机器人运行、多引擎迁移、完整有限元护套压扁、塑性破坏、复杂束线自接触、任意五轴加工、任意图案加工、遥操作设备接入、LeRobot 数据流水线、策略训练、大模型规划和公开排行榜。

本轮参考控制器可以读取真实中心线和线夹状态，但必须标为 **privileged/state-based baseline**。这证明任务在当前模型下可解，不证明视觉策略、触觉策略或 VLA 已经完成任务。

原生灵巧手可以继续作为已有配置选项，但本轮裸线布线先验证双指夹爪；不把不同末端执行器共享外观配置等同于均已通过布线验收。

## 5. 物理组件如何补齐

### 5.1 P3：继续使用当前线束模型

复用 Flex 的实际碰撞与轴向力，以及 `CableMechanics` 的弯曲力。为布线增加自由线束初始化和中心线查询，避免直接复用必须带刚性端头的任务构建器。

线束长度、外径、单位长度质量、轴向刚度、弯曲刚度、阻尼、摩擦、最小允许弯曲半径、张力报警/失效阈值仍由场景提供。端头若存在，单独声明质量和连接关系；布线主线不能借隐形端头或世界锚点托住线。

需要输出按材料弧长索引的局部信息：节点/边位置、局部边张力、曲率估计、与夹爪/线夹的接触。现有全线最大张力适合做总上限审计，不能直接当作每个抓点附近的张力。

当前模型不预测护套压痕和挤压损伤。首版通过夹持力上限、接触穿透、曲率和张力限制报告模型有效范围，不把没有形变模型的“未压坏”声明成真实材料结论。

### 5.2 P3：新增弹性侧向线夹

推荐采用固定底座、容纳圆线的夹座、两侧可恢复弯曲的夹臂及向内的唇边。首版在截面平面内建模夹臂变形，沿线方向有有限夹持宽度。

复用现有分段弹性梁建模方法，但线夹的几何、局部坐标、接触面和观察器独立实现。不能直接复用“插头是否退出肩部”的判定。

线束通过实体接触撑开夹口，越过唇边后夹臂回弹。进入、保持、滑动和退出都由相同的模型决定。禁止在观察到 `captured` 后增加 weld、关闭碰撞、改质量或把线束固定到夹座。

首版选择开口小于线径、夹座容得下线径、夹臂允许形变足以让线通过的工况。尺寸、刚度、摩擦、允许形变和穿透容限需联动校验，不能各自填一个数字就声称组合可行。

若分段梁不足以表现需要的夹臂运动，先记录台架问题并调整这个局部组件；不因此重建整个材料框架。超出弹性范围只报告模型失效，不播放没有物理依据的断裂效果。

### 5.3 P2：真正抓住裸线

现有端头抓持函数不能覆盖 Flex 接触。新检查应识别夹爪两侧指垫接触到的 Flex 元素，跟踪其材料弧长位置，测量持续接触和相对滑移。

不能只看闭合量、中心线距离或某一个节点是否贴近手指。Flex 接触可能没有普通刚体 geom ID，必须正确处理接触中的 flex/element 信息，不能沿用过滤负 geom ID 的刚体检查逻辑。

先检查现有指垫是否适合线径。如需 V 形槽或较窄指垫，应作为具名、可选择的真实几何配置，纳入质量/碰撞/可达性检查；不能用不可见夹持盒或线束刚性替身。

第一种策略优先采用两手夹住插入点两侧、协同压入，减少额外工具需求。线夹唇边及板面必须为夹爪留出可达空间；若需要压线附件，应作为范围变更说明，不能悄悄增加第三只手。

### 5.4 必须先通过的数值检查

比较线束分段数、夹臂分段数、物理步长与接触参数对插入力、最大穿透、保持和拉脱的影响。重点防止线束从粗分段夹口穿过，或数值穿透被误认为插入成功。

细化前后应保持相同材料含义；分段数量改变时正确换算轴向边刚度/阻尼和梁参数。台架通过后才接入长任务，不能靠大规模调控制器掩盖接触模型不成立。

## 6. “任务成功”到底如何定义

### 6.1 三个层次必须分开

| 层次 | 例子 | 谁负责 |
| --- | --- | --- |
| 物理事实 | 接触在哪条边、夹口张开多少、局部张力多少 | Core 观察器 |
| 任务关系 | 指定线束已进入夹座、指定路径已覆盖、双手已离开 | 可复用任务判据 |
| 策略阶段 | 正在取线、换抓、重试第 2 个线夹 | 参考控制器 |

成功只能由前两层得到，不能读取控制器的 `done`、目标位姿或当前阶段来证明完成。控制器与任务可读取同一份目标配置，但评价实际结果的几何算法不能照搬控制器轨迹完成检查。

保持现有 `TaskSpec.evaluate(state, audit)` 入口，按实际需要增加类型明确的布线状态。状态复制与只读数组需要落实；`frozen=True` 本身不能保证数组和嵌套字典不可改。

### 6.2 单个线夹的判定

拟议状态为 `outside / entering / seated / retained / escaped`，这些是观测标签，不是物理锁。

`seated` 至少要求指定线束的一段中心线进入夹座内部、处在唇边后方、通过正确开口且几何/穿透在有效范围内。计算使用线段与夹座关系，不只检查离散节点，也不以“与线夹接触过”为充分条件。

`retained` 还要求夹口恢复到允许范围，外部夹爪不再托住该区域，并持续满足保持条件。正常夹持可能没有持续可测的每一对接触，因此不能要求某个固定接触对永久存在；需结合几何闭合、时间保持和独立拉脱检查。

一旦线束逃出，当前固定数量必须减少；历史 `ever_captured` 事件只用于解释过程，不能永久累加成成功。

### 6.3 整条路径的判定

目标定义为“按线束弧长依次经过哪些线夹、各段允许处在哪个路径走廊、转角允许多小、自由端应在哪个区域”。

验收至少包括：

- 指定线夹全部保持了同一根目标线；没有漏夹、错夹或仅外侧擦过。
- 沿线束材料弧长匹配线夹顺序，不能让同一个局部线段同时冒充多个目标点。
- 线夹之间的中心线满足路径走廊及板面法向距离要求；自由端单独定义目标区，不误用全线最大误差。
- 转角半径满足要求；矩形路径在角处圆滑过渡。
- 两手张开并退离规定检查区域，不能用手掌、手背或机器人身体继续支撑线束。
- 所有关系在指定仿真时间内持续成立；发生超限的历史仍能使本回合失效。

几何上的线夹顺序与控制器“先装哪个”的操作顺序分开。只要工艺没有额外限制，换一种合法装配顺序也可以成功。

### 6.4 最终成功、质量与失败

正式回合成功建议定义为：

```text
全部目标线夹当前有效保持
且 路径、线夹顺序、自由端与转角满足目标
且 双手已经松开并退离
且 连续稳定保持达到 hold_time_s
且 回合未触发禁止的载荷/碰撞/数值失效
```

终态稳定速度阈值、保持时长及采样频率在 R1 冻结；时间使用仿真时钟，不能用播放帧数或电脑运行秒数代替。

带小幅拉扰动的保持检查作为**独立审计**：在统一冻结的力、方向、作用位置和持续时间下复查脱扣。审计外力必须被记录，并与策略回合指标分开。台架可做完整拉脱曲线，机器人评测不必每次拉到模型失效。

结果分为 `success / failure / timeout / invalid / error`。`invalid` 表示越出模型适用范围或数值不可信，`error` 表示程序/资源等异常；都不能从成功率分母里悄悄剔除。统一映射现有 `terminated/truncated/success/failure_reason`，不强迫旧任务一次性改写。

报告包括完整任务成功率、当前保持数量、最大路径偏差、最小弯曲半径、峰值/局部张力、夹持与压入力、滑移量、重试次数、仿真时长和计算耗时。单步成功率与整体成功率分开。

## 7. 场景菜谱和架构变化

### 7.1 保持原来的索引关系

```text
scene_config.yaml ── 场景/线材/线夹/机器人/工位/初始化
constraints.yaml ─── 载荷、碰撞、几何容差、稳定保持等限制
task_spec.py ──────── 目标路径、目标关系、成功/失败判据
        │
        ▼
场景校验 → 具名构建器 → MuJoCo 模型 + 材料力 + 接触
                                   │
                         只读物理状态与审计
                                   │
                       TaskSpec → TaskResult
                                   │
                    报告 / 回放 / 视频 / 网页

参考控制器读取目标及观测，通过机器人动作影响物理；
它不写入线夹保持状态，也不替任务判定成功。
```

同类场景优先改 YAML；`task_spec.py` 使用一个可复用的布线任务类。暂不增加第二套目标文件格式，也不建通用工作流语言。

一个字段只设一个权威来源：材料属性放场景，安全边界放 constraints，任务目标由 task_spec 读取场景目标并组合。禁止控制器再复制一份独立容差表。

### 7.2 拟议配置内容

下面是字段结构草案，**不是当前校验器已经接受的可运行 YAML**。实际 schema 在 R1 冻结，不把缺少的尺寸和物性默认为任意数值。

```yaml
  frame: board
  mounting: fixed_vertical

  material_profile: demo_round_cable  # 指向场景内明确的物性配置
  source: provisional

    profile: elastic_side_entry     # 明确几何、梁参数及开口方向
  - id: clip_02
    profile: elastic_side_entry

  ordered_clips: [clip_01, clip_02]
  route_profile: straight
initialization:
  mode: supply_fixture             # assisted_grasp 只用于单独的调试模式
```

完整配置还应包含：板位姿/尺寸；各线夹位置与朝向；线夹开口、夹座、唇边和梁尺寸；线束物性与长度；供料架实体几何；目标路径及自由端区域；机器人末端配置；求解步长及控制频率；相机；变体随机范围和种子。

校验器必须拒绝未知字段、非有限数值、错误单位/范围、重复对象 ID、引用不存在的线夹、目标路径越板、明显不可达/线长不足的布局，以及没有声明适用范围的自交路径。可达性静态检查与实际试运行分别报告，不能把静态检查通过当作动态可解。

## 8. 分阶段执行清单：R0–R9

主线共 **10 个阶段、50 项任务**。每阶段五项，必须同时完成实现、检查和证据记录才可标记通过。阶段内可做独立准备，但不能跳过尚未成立的物理门槛宣布下游成功。

### R0：冻结当前事实和本轮边界

| 编号 | 动作 | 交付与检查 |
| --- | --- | --- |
| R0-01 | 记录工作区、源码、依赖、资产来源与当前分支 | 不清理用户未跟踪文件；新工作以批准时的实际 HEAD 为准 |

## 9. 验收矩阵与计算成本

以下是建议批准的首版门槛。物理量容差需要 R1 按选定几何/物性冻结；不能直到机器人演示失败后才选择一个方便通过的数值。

| 层级 | 最小验证 | 通过要求 |
| --- | --- | --- |
| 配置与判据 | 正反配置、弧长顺序、夹外擦碰、重复匹配、松手、事件/时间、reset | 自动化用例全部通过；缺少关键输入不能返回成功 |
| 裸线/线夹台架 | 默认插入/保持/拉脱；至少 3 档张紧；错误开口/位置与过载 | 机械行为与记录一致；不得通过任务逻辑补物理 |
| 数值检查 | 默认步长与减半；线束/夹臂分段分别细化 | 成功/失效分类一致；默认峰值压入力与保持位移的差异建议不超过 15%，接触穿透满足 R1 冻结上限 |
| B1 单夹 | 开发种子 0–9 | 至少 9/10 完整成功；所有错误动作检查不得误报成功 |
| B2 直线 | 开发种子 0–9 | 至少 9/10 完整成功 |
| B3 L 形 | 开发种子 0–9 | 至少 8/10 完整成功 |
| B4 开口矩形 | 开发种子 0–9 | 至少 8/10 完整成功 |
| 保留样例 | B2–B4 各种子 100–109，R7 前不用于控制器调参 | 每场景至少 8/10；与开发样例分表，报告完整分母 |
| 有效参数变体 | 板位姿、夹距、材料各 1 个冻结变体，在 B3 各运行 5 个种子 | 每变体至少 4/5；其范围先通过物理有效性检查，不混合成单一平均数 |
| 最终保持审计 | 每类任务至少 3 个冻结种子施加同一规格的小扰动 | 无脱扣；失败回到保持设计或任务质量问题，不能只重拍视频 |
| 旧功能兼容 | 交接、张力、舌片、拔出放置和三种加工目标 | 至少各 1 个完整代表回合；修改到的共同物理模块追加原有相关矩阵 |
| 发布可用性 | 新检出、最小任务、模板变体、离线网页、连续两次 GUI 回合 | 无私有历史目录依赖；回合/reset/关闭行为正确 |

15% 是本轮拟议工程稳定性门槛，不是对真实材料误差的承诺。位移接近零时使用 R1 冻结的绝对容差，避免相对误差无意义。若峰值对细化敏感而整体行为稳定，应补充冲量/准静态载荷对照并解释，不能静默删除峰值指标。

R1 先确定随机化分布；同一个种子必须能生成相同的场景配置。保留样例也不是无限次调参集。变体失败、资源异常和轨迹缺失应各自列出，不能算作“没运行所以不用统计”。

考虑现有工业仿真较慢：先单 worker 台架和短回合，发现问题早停；通过后再跑长矩阵。记录构建、步进、策略、记录、渲染和编码耗时，分别给出仿真秒数、墙钟秒数与步进 RTF。并发数量依据内存预检，默认不重启全部历史长测试。

网页视频可按仿真时间重采样到正常速度，允许倍速播放；**不把视频流畅误写为仿真实时运行**。不设必须达到实时的本轮门槛，但应给出当前机器上的可复查速度。

## 10. 可视化与社区使用

### 10.1 延续现在有效的展示方式

保留现有 [`demo_videos_20260928/index.html`](../artifacts/demo_videos_20260928/index.html) 的本地视频展示体验。该链接是当前工作区的本地产物，通常不随 Git 克隆提供。

新交付建议包含：

- 正面全景：双臂、整条线和目标路径。
- 侧面近景：线束撑开夹口、越过唇边和回弹。
- 状态叠加：线夹编号与当前保持状态、路径误差、张力、重试原因。
- 完成后的松手保持片段；至少一段未入座/过拉/脱扣反例及解释。
- 每条视频旁显示任务目标、种子、源码/配置身份、报告链接和模型限制。

优先复用四视图或已有审阅布局，不另建复杂 Web 仿真系统。视频离线可打开，目录使用相对路径；新导出器通过显式 manifest 读取资料，不要求访问作者机器上的历史 worktree。旧演示保留原始来源，不能用新模型强行解释旧轨迹。

### 10.2 新贡献者的最小路径

1. 安装项目，查看任务目录和单夹说明。
2. 复制布线模板，调整线夹位置、路线、线长及合规物性。
3. 运行配置检查，查看可达性/线长/开口匹配提示。
4. 运行参考控制器并查看独立任务结果。
5. 执行最小验证，生成轨迹、报告和视频。
6. 提交场景与说明；大型视频通过约定的发布附件共享，避免自动塞入源码仓库。

`task_spec.py` 是受信任的 Python 场景代码，当前加载器不是安全沙箱。模板化贡献可以降低接入成本，但不能宣称任意外部脚本可安全自动运行。资产来源与许可沿用现有要求。

## 13. 本次审阅建议确认的范围

1. **版本方向：**以 Core-0.2 任务候选版为目标，物理底座沿用 0.1；旧 G9 状态单独保留，正式版本和主分支合并不在本次写计划时发生。

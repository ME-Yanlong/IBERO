## 1. 项目定位与竞争格局

IBERO（Industrial Bimanual Embodied Robotic Operations Benchmark）：开源工业级双臂具身智能操作基准平台，覆盖精密装配（Assembly）、无损拆解（Disassembly）、绿色再制造（Reman）全生命周期，以**工业接触力学保真 + 双臂力位协同 + F/T 力觉观测流 + 无损性多指标评测**为差异化核心。

### 1.1 竞争格局（2025–2026）

| 基准 | 构型 | 引擎 | 任务域 | 力觉流 | 多指标评测 |
|---|---|---|---|---|---|
| LIBERO (NeurIPS'24) | 单臂 Franka | MuJoCo+robosuite | 桌面/厨房 130 任务 | ✗ | 成功率+终身学习指标 |
| BiGym (CoRL'25) | H1 上身双臂+2F-85 | 纯 MuJoCo+gymnasium | 家庭 40 任务 | ✗ | 成功率 |
| RoboTwin / 2.0 | 双臂（多构型） | Isaac / SAPIEN | 通用操作 | 部分 | 成功率+DR 鲁棒 |
| RoboDojo (AI2) | 双 ARX-X5 | Isaac Lab | VLA 评测 42 任务 | ✗ | 得分×成功率 |
| ManiSkill3 (RSS'25) | 单臂/双臂 | SAPIEN GPU 并行 | 通用+real2sim | ✗ | 成功率 |
| **IBERO（本项目）** | **G1 等国产人形上身双臂** | **MuJoCo+Flex** | **工业装配/拆解/再制造** | **✓ 6 轴 F/T 双腕** | **成功率+无损率+内力超限率+自碰撞率+OOD** |

**结论**：双臂已不稀缺，IBERO 的护城河必须做深三条线——工业接触力学（螺纹/卡扣/胶粘/线缆）、力觉观测与力控指标、无损性约束。否则会沦为"又一个双臂 pick-place 基准"。

## 2. 已确认技术决策（2026-09-06）

1. **主引擎**：MuJoCo 3.x（含 Flex 软体 + 机器人模型来自 MuJoCo Menagerie），Isaac Sim 保留为"保真度验证与缺口补位"后端；场景规格引擎无关（YAML 语义化参数）。
2. **底座路线**：**纯 MuJoCo + Gymnasium 自研**，不依赖 robosuite（仅移植其 OSC/IK 控制器部件作参考）。依据见 3.3。
3. **主力构型**：Unitree G1 上身（7-DoF 双臂 ×2，Menagerie 官方维护、含 MJX 变体）；Booster T1 因原生臂 4-DoF、无腕无手，需加腕+夹爪改造，列入路线图后置。
4. **算力环境**：实验室 Linux GPU 服务器（训练/评测）；本机 Windows 开发仿真底座。
5. **阶段一 MVP**：单场景端到端全链路打穿（建模→示教→训练→多维评测），验证架构后再铺开 4 种子场景。

## 3. 参考基座调研结论

### 3.1 LIBERO（NeurIPS'24）——基准设计基因库（源码级调研）

**示范数据集 HDF5 schema**（每任务 50 条，`datasets/<suite>/<task>_demo.hdf5`）：
- `data/demo_i/obs/`：`agentview_rgb`、`eye_in_hand_rgb`（128×128×3）、`gripper_states`(2)、`joint_states`(7)、`ee_states`(6)、`ee_pos`(3)、`ee_ori`(3)
- `actions` (T,7)：OSC_POSE `[dx,dy,dz,ax,ay,az,gripper]` ∈ [-1,1]；`states` (T,flat)：MuJoCo 全状态平坦化（确定性回放与质控）；`rewards/dones`：稀疏，末帧=1（done 即"成功"）；attrs：`bddl_file_content`、`problem_info`、`num_demos=50`（完整性脚本硬编码校验）
- 训练只喂 rgb+proprio，物体 GT 观测仅作评测判据——与 IBERO 设计一致

**Env 接口**：`OffScreenRenderEnv`（gym 0.25 风格、不注册 make）→ `BDDLBaseDomain`（robosuite SingleArmEnv 子类）；OSC_POSE 7 维、control_freq=20、horizon=1000；obs：`agentview_image`、`robot0_eye_in_hand_image`、`robot0_eef_pos/quat`、`robot0_gripper_qpos`、`robot0_joint_pos`；自研 `SubprocVectorEnv` 多进程评测。

**BDDL 声明式任务规格**（regions/fixtures/objects + init 谓词 + goal 谓词三层）：
- `(:regions ...)`：`(:target <锚定物>)` + `(:ranges ((x y x y)…))` + 可选 `(:yaw_rotation)`；关节物体上的 region 由 MJCF `<site>` 自动提取（affordance 机制）
- `(:init ...)` 谓词：`On/In/Open/Close/Turnon/Turnoff` → 决定初始摆放采样与关节初值；`(:goal (And ...))`：同套谓词合取，`ObjectState` 几何实现（接触+高度+xy 阈值）
- 示例（libero_spatial 捡碗任务，节选）：`(define (problem LIBERO_Tabletop_Manipulation) (:language Pick the akita black bowl …) (:regions (plate_region (:target main_table) (:ranges ((0.05 0.19 0.07 0.21)))) …) (:fixtures main_table - table …) (:objects akita_black_bowl_1 … - akita_black_bowl …) (:init (On akita_black_bowl_1 main_table_between_plate_ramekin_region) …) (:goal (And (On akita_black_bowl_1 plate_1))))`

**程序化生成管线**（双向）：任务→BDDL：场景模板类（`@register_mu` 声明 fixture/object 品类数量、区域、init 状态元组）→ `task_generation_utils` → `bddl_generation_utils` 装饰器生成器拼文本；BDDL→MuJoCo：`bddl_utils`（bddl 1.0.1 解析）→ `@register_problem` 场景组装类（arena+fixtures+objects+region→site+三级 placement sampler）→ `ManipulationTask` 合模。

**评测可复现性机制（最有价值的遗产，IBERO 原样移植）**：`.init/.pruned_init`（torch pickle，~50 个剪枝初始态的平坦 MuJoCo 状态）随仓库分发，评测固定在这 50 个初始态循环取用；演示回放用 `states[0]` 恢复初始态逐帧校验（偏差>0.01 告警）。

**策略栈**：BCTransformer（ResNet18-4 层 + FiLM(BERT) + 时序 TransformerDecoder + 5 模态 GMMHead）、BCViLT（patch+空间 Transformer）；AdamW 1e-4、50 epoch、batch 32、seq 10、128×128 双相机、n_eval=20×max_steps 600。GMM 头输出维度由 shape_meta 自动推导→双臂 14 维零改动（IBERO 基线用 LeRobot 实现时同理）。

**依赖教训**：robosuite（官方、未锁版本）+ robomimic 0.2.0 + bddl 1.0.1 + gym 0.25.2——**robosuite/MuJoCo 不锁版本是复现性隐患**；IBERO 必须锁定（接触行为对 MuJoCo 版本极其敏感）。

**继承 / 重写判定**：

| 继承（移植进 IBERO 的设计） | 重写（IBERO 自研） |
|---|---|
| BDDL 声明式规格与谓词体系——新增 `Inserted/ForceBelow/Screwed` 等谓词即可扩展工业语义 | 单臂→双臂 env 基类（robot0 硬编码、双 eef 相对观测、手-物指派） |
| Benchmark 层：Task NamedTuple + 注册表 + 固定剪枝初始态 + task_orders | 动作空间 7→14 维全链路（数据集/step/评测/策略头） |
| HDF5 schema 哲学：确定性回放 + 完整性校验 + 双通道分发 | **接触力学：LIBERO 无任何力观测/接触调参/稠密奖励——IBERO 核心自研** |
| 策略网络结构（GMM 头自动适配双臂维度） | placement sampler 需加双臂可达性/工作区划分 |
| 许可：代码 MIT、数据集 CC BY 4.0 | 遥操作采集路径（工业双臂需重做） |

### 3.2 BiGym（CoRL'25）——路线最接近的先例

关键事实（master 分支源码核实）：
- **技术栈**：纯 MuJoCo 3.1.5 + gymnasium（个人 fork）+ dm_control pyMJCF + 自研 mojo 封装，**无 robosuite、无 lerobot**。
- **构型改造**：H1 完整 XML 运行时裁剪（删腿/torso 关节与执行器、保留视觉网格），代码插入 1-DoF 腕关节，Robotiq 2F-85 独立 XML 挂装到腕部 site；**动作空间 [基座3 | 双臂10 | 夹爪2] = 15 维**（基座 X/Y/RZ delta）。
- **任务定义**：任务 = env 子类 + preset YAML（道具组合）+ `_success()/_fail()` 纯物理条件判定；稀疏成功奖励；`terminated=success|fail`，`truncated=unhealthy`。
- **遥操作**：Valve Index VR（OpenXR），HMD→基座、双手柄→双臂 IK（用 MuJoCo position actuator 的 refsite 特性迭代求解，腕角解析式）、扳机→夹爪 0/1。
- **数据**：safetensors 演示（metadata 完整可重放、500 Hz 采集、可降采样）；每任务 50 条人工演示；评测 50 episode、末 3 checkpoint 平均；IL 150K 步 / RL 100K 步。
- **基线**：ACT（ALOHA 版）、Diffusion Policy（两骨干取优），训练配置见论文附录 C；**bigym-bench 基线仓库已 404 下线**，需自行实现或直接用 LeRobot 框架。

对 IBERO 的可继承项：
1. 运行时 XML 裁剪 + 代码插腕/挂夹爪的改造模式（直接套用到 G1）；
2. Robotiq 2F-85 挂装方案（1-DoF 动作 [0,1]、pad 碰撞判抓取、标准/精细两套 XML）；
3. 任务 = 类属性 + preset YAML + 纯物理成功条件（适合"成功=工艺条件满足"的工业语义）；
4. 评测协议（50 demos + 50 rollouts + 末 3 ckpt 平均）——轻量可复现，社区可对标；
5. 采集 500 Hz + 降采样 + metadata 完整重放的数据管线模式。

不适用/需改造项：移动基座与腿部（工业工位直接 weld 骨盆）；依赖过度 pin（gymnasium fork、mujoco==3.1.5、pyopenxr<1.1.5001）——IBERO 一律用主流版本（gymnasium 官方、mujoco 最新稳定、LeRobot 官方包）；家庭任务语义改为工艺语义。

### 3.3 机器人模型与引擎能力核查（MuJoCo Menagerie / robosuite）

**Menagerie 模型实测（XML 核实）**：

| 模型 | 臂 | 手/腕 | 驱动 | 相机 | 许可 | 备注 |
|---|---|---|---|---|---|---|
| unitree_g1 | 7-DoF×2（肩3+肘1+腕3） | `g1.xml` 橡皮手 / `g1_with_hands.xml` Dex3-1（7 DoF/手） | 全部 position 执行器（kp=500） | 无（需自加） | BSD-3-Clause | **`g1_mjx.xml` MJX 变体（经 MuJoCo Playground 实机迁移验证）** |
| booster_t1 | **4-DoF×2，无腕** | 刚性手造型，零手指 DoF | position（kp=75） | 无 | Apache-2.0 | 抓取任务必须自加腕关节+夹爪 |
| unitree_h1 | 4-DoF×2，无腕 | 无手 | 力矩 motor（肩±40/肘±18 N·m） | 无 | BSD-3-Clause | BiGym 改造同源 |
| robotiq_2f85 | — | 1-DoF 夹爪（general 执行器+腱均分） | — | — | BSD（ROS-Industrial） | 另有 v4 与 MJX 变体 |
| unitree_z1 | 6-DoF 臂 | z1_gripper 1-DoF | general | 无 | BSD-3-Clause | 备选轻量臂 |

**robosuite v1.5.2 现状**：`bimanual.py` 已移除（重构为 Robot 基类），双臂支持靠 Baxter/GR1（Fourier 人形，含 fixed-lower-body 模式）；OSC_POSE/IK_POSE 控制器双臂开箱可用；**GRIP 夹爪抽象只面向 1-DoF 开合**，Dex3-1 等灵巧手必须绕开其最核心的动作抽象层；版本锁定 mujoco>=3.3,<3.10。

**底座路线结论（纯 MuJoCo + Gymnasium，三重依据）**：
1. G1/T1 移植进 robosuite 需重写 model class + 控制器配置，而 Menagerie 模型即插即用、随 MuJoCo 更新维护，G1 还有官方 MJX 变体；
2. 接触力学自由：robosuite 环境循环附加了自己的接触判定逻辑，阻碍 condim/solver 调参与接触对精简——这正是工业基准对保真的核心诉求；
3. BiGym 已在该路线上完成 H1 上身改造先例，社区可对齐；所需自研量（OSC/IK 控制器、gymnasium env、任务层）恰是基准平台的核心产出，值得自己掌控。

## 4. IBERO 总体架构

沿用方案文档分层（评测层 → 套件层 → 底座层），代码落地为 monorepo：

```
ibero/
├── docs/                 # 方案、可行性、规范（本文档所在）
├── ibero-core/           # 双臂 MuJoCo 底座（阶段一核心）
│   ├── robots/           #   G1 上身等构型（Menagerie 裁剪+夹爪挂装）
│   ├── physics/          #   PhysicsBackend 抽象 + MuJoCo 实现（接触/断裂/形变）
│   ├── controllers/      #   OSC/IK/双臂导纳-阻抗力位控制（移植自 robosuite 参考）
│   ├── envs/             #   IBeroEnv (gymnasium) + 渲染 + 审计流
│   └── schema/           #   Canonical Schema v1 + 校验器
├── ibero-suites/         # 场景库：scene_config.yaml + task_spec.py + assets + demos
├── ibero-record/         # 双臂采集：脚本/规划器/VR 后端 → LeRobot 数据集
├── ibero-cli/            # create-scene / check / teleop / train / eval
├── ibero-eval/           # IBERO-Metrics（成功率/无损率/内力超限/自碰撞/OOD）+ Leaderboard 工具
└── ibero-baselines/      # ACT / Diffusion Policy /（可选）OpenVLA 微调
```

场景标准目录（承接方案文档 5.1）：`scenes/<scene_id>/{assets/, scene_config.yaml, task_spec.py, constraints.yaml, demonstrations/}`。

## 5. IBERO-Core 技术方案

### 5.1 统一数据与动作接口（Gymnasium / ROS 2 / LeRobot）

**逻辑**：三个接口对应三类生态，不做三选一，也不做三协议合一；统一发生在 **Canonical Schema** 层，三个接口都是它的投影。

```
  算法生态   Policy (ACT/DP/VLA)  ←→  Gymnasium API   ← 唯一运行时接口
  数据生态   ibero-record  ←→  LeRobot 数据集  ←→  回放/训练   ← 数据层兼容
  工业生态   (阶段二) ROS 2 桥：真机/传感器/遥操作硬件        ← 只冻结契约
                ↑ 三者共享同一份 Canonical Schema ↑
```

**Canonical Schema v1 草案**：

```yaml
# 动作空间（策略 20 Hz；物理 500 Hz，控制律插值/子步）
action_mode_ee:   [Δx,Δy,Δz,Δr,Δp,Δy,grip] ×2   # 每臂 7 维 = 14 维，m/rad，grip∈[-1,1]
action_mode_joint: [q1..q7, grip] ×2            # 关节位置模式（BiGym 式，备选）
# 观测空间（策略 20 Hz）
observation.images.cam_head / cam_wrist_l / cam_wrist_r   # RGB(+depth)，相机自加
observation.state.ee_pose_l / _r (7+7)  gripper_width_l / _r
observation.state.qpos / qvel           # 双臂关节
observation.state.wrench_l / _r         # 6+6 维 F/T —— IBERO 独有
observation.state.object_states         # 工件位姿（训练可用，评测仅供判据）
# info 审计流（不进模型，专供 IBERO-Metrics）
info.audit = {contact_events, damage_flags, internal_force_est, self_collision_flags}
```

LeRobot 兼容：双臂/F-T 流以新增 key 扩展（`observation.state.wrench_*`），向后兼容其 dataset viewer 与 `lerobot` 训练入口。ROS 2：阶段一只冻结 topic/msg 契约（`/ibero/ee_delta_{l,r}`、`/ibero/wrench_{l,r}` …）。

**任务书 IBERO-Core-01（统一接口层，单人 2–3 周）**：

| 项 | 内容 |
|---|---|
| 输入 | Schema v1（冻结）；物理底座最小可用版（Core-02）；G1 裁剪 XML；参考 BiGym obs/action 约定与 LeRobot 训练入口 |
| 交付 1 | `IBeroEnv(gymnasium.Env)`：reset/step/headless 渲染、space 严格声明、info 审计流 |
| 交付 2 | `ibero/schema/`：schema 定义 + pydantic 校验器 + `ibero check-env` |
| 交付 3 | `ibero/data/lerobot_adapter.py`：env→LeRobot 写出、数据集→env 回放 |
| 交付 4 | `docs/ibero_ros2_contract.md`（阶段二契约冻结，仅文档） |
| 验收 A1 | `gymnasium.utils.env_checker.check_env` 通过；reset 20 种子可复现 |
| 验收 A2 | 20 条脚本示范→LeRobot 数据集→**不改代码**跑通 LeRobot ACT 训练 |
| 验收 A3 | 数据集回放位姿误差 < 1e-4（确定性质控） |
| 验收 A4 | 评测输出含四项 IBERO-Metrics 的 `metrics.json` |
| 边界 | 控制律由 Core-02 提供 `compute_action()`；本任务只管协议与数据搬运 |

### 5.2 高保真物理仿真与断裂/形变接触力学

**结论**：用 MuJoCo 3.x + Flex；**断裂、胶粘、螺纹在 Isaac/PhysX 同样无原生支持**，两引擎差距在渲染/软体成熟度/工具链，不在接触力学本身。"高保真"= 约束抽象 + 参数标定 + 对标验证。

| 机制 | MuJoCo 实现途径 | 备注 |
|---|---|---|
| 微间隙配合（0.5mm） | 求解器调参（elliptic cone、condim 4/6、solref/impratio）+ 高精度凸分解网格（coacd/V-HACD） | 关键在几何保真 |
| 柔性线缆 | MuJoCo Flex（FEM：composite 线缆/膜） | 原生软体 |
| 卡扣形变/突变力 | 卡爪小块 Flex 实体 + 刚性座；或刚性卡爪 + breakable 约束 + 摩擦标定 | 标定是核心 |
| 胶粘剪切 | 可断裂 weld 约束：equality + 力阈值触发失效 | 两引擎均需此抽象 |
| 螺栓旋出 | 螺旋耦合关节（转动↔平动耦合 + 摩擦扭矩标定到真实拧紧力矩） | 业界仿真通用妥协 |
| 断裂/破损判定 | 力/应变阈值 → 约束失效或预分割件 bond 断裂；损伤标志进 info 审计流 | 判定逻辑自研 |
| 6 轴 F/T | MuJoCo 原生 site force/torque 传感器或接触求和 | 健壮且免费 |
| 并行规模 | MJX（刚性场景）；Flex 场景 MJX 受限，MVP 的 50 条示范用 CPU 多进程即可 | g1_mjx.xml 已有 |

**验证闭环（"高保真"的操作性定义）**：每个机制一个物理标定场景，与文献/实物对标——螺栓拧出扭矩–转角曲线、卡扣脱开力峰值、胶粘剪切破坏阈值、压装力–位移曲线；误差写入文档（fidelity envelope）。**没有对标数据的机制不进 MVP。**

**引擎无关抽象**：`PhysicsBackend` 接口 = `load(scene_yaml)→world / step(dt) / read_sensors() / contact_report()`；场景 YAML 声明语义化物理参数（摩擦/刚度/断裂阈值/约束类型），MuJoCo 编译器生成 XML/插件，未来 PhysX 编译器消费同一份 YAML。断裂=breakable constraint、形变=Flex 实体、螺纹=螺旋耦合关节——这些抽象两引擎均可落地，抽象层才成立。

### 5.3 双臂导纳/阻抗力位控制与内部力（下一讨论议题）

待展开：双臂导纳/阻抗混合控制律库、一手定压支撑+一手自适应作业的力位解耦、内部力（internal force）的数学定义与仿真测量（IBERO-Metrics "内力超限率"的前提）。

## 7. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| R1 接触力学保真达不到宣称（卡扣/胶粘/螺纹） | **高（头号）** | 标定+对标闭环；无对标数据的机制不进 MVP；Assembly 压装为 MVP 首选（物理风险最低）；Isaac 作保真验证后备 |
| R2 双臂示教数据质量差/不可复现 | 中 | MVP 用脚本/规划器示范打通链路，VR 遥操作并行开发、数据后换 |
| R3 OpenVLA 微调算力/数据不足 | 中 | 首期以 ACT/DP 为主基线（150K 步级预算）；OpenVLA 列为可选 |
| R4 社区采纳失败（没人用） | 中 | LeRobot 原生兼容 + 50 demos 轻量协议 + 官方 baseline 成绩随仓库发布 |
| R5 引擎无关抽象过度设计拖慢进度 | 低 | 抽象只到 PhysicsBackend 接口层；首期只实现 MuJoCo 后端 |
| R6 依赖版本漂移破坏复现性 | 中 | 锁定 mujoco/lerobot 版本于仓库；接触行为对 MuJoCo 版本敏感，升级需过回归标定测试 |

## 对 V3 的主要校订

| 原内容 | V4 处理与理由 |
|---|---|
| 第 8–11 页：软硬件 / 仿真器 / 接口 / BMS 的待填占位页 | 用当前仓库可核查的 Core 架构、求解职责、协作边界和 BMS 扩展路径补齐；不保留“文字或图发给我”占位文字 |
| Core 中双 Franka、双 UR、ALOHA 及多种接触机制容易被理解成全部已支持 | 当前实现明确为 MuJoCo + G1 上半身及场景工具；线束 / 卡扣 / 铣削为已实现机制，其它构型与机制仍为后续目标 |
| 接口与数据工具混合描述 ROS 2、LeRobot、遥操作和现有能力 | 区分现有场景 CLI、NPZ 证据轨迹、JSON 报告，与后续遥操作、标准训练数据及统一接口；不扩张当前 Core 范围 |
| 早期 capsule-chain / Flex 路线可能产生混淆 | 以现行配置为准：线束已经采用一维 MuJoCo Flex；卡扣默认分段被动弹性梁，三维实体 Flex 候选不是现行默认 |
| 谐波减速器页出现 ±0.02 mm、±0.5 N、1 ms、±0.005 mm 等设备或成品指标 | 未发现相应选型 / 实测依据，重画为候选工艺页并去掉既成实绩式表述，保留双臂分工与工艺逻辑 |
| BMS 拆解示范占位容易误解为完整场景已交付 | 明确当前卡扣与线束仅提供可复用机制；完整 BMS、螺纹、胶粘、电气与热安全等仍需建设 |
| 原首发页列出四套种子场景与 ACT / Diffusion Policy / OpenVLA 等模型 | 改为五类现有任务环境与七段演示，明确当前基线是脚本控制器，学习策略与大规模 benchmark 尚未交付 |
| 成功率、无损、内力、自碰撞、泛化指标 | 保留原方案的五类目标，但区分当前能观察的阈值与审计、以及真实损伤预测 / 形式化安全 / OOD 等尚不能外推的能力 |
| 示教 30–50 条与统一 `ibero-cli` 贡献流程 | 当前共建先交付对象、菜谱、正反例及证据；专家示教数量是后续数据建设目标，不是当前材料组件贡献前置 |

| 对其它机器人基准的概括较绝对 | 改为工业接触与工艺评测的需求说明，不一概否定现有工作的接触或协同能力 |

这些修改没有改变最初方案的工业双臂、开放基准、社区共建方向；主要是把**总体愿景、当前可运行原型、待验证能力**分开说明。

## 必须保留的技术边界

1. 当前是仿真机器人，不是通过宇树 SDK 控制真实 G1。
2. 一维 Flex 线束不是多层导体 / 护套三维实体应力；卡扣梁模型不代表塑性、疲劳或断裂都已实现。
3. 卡扣由真实几何接触阻挡；按压造成变形与净空，状态标签不执行魔法解锁。
4. 加工采用固定体素工件与过程级平均载荷；不是切屑塑性断裂 FEM。飞屑仅视觉效果。
5. 铣削由左臂执行，右臂停放；不能宣称已经完成双臂协同铣削。
6. 示例材料与加工系数尚未实测标定；阈值内运行不是工业无损认证。
7. 视频是对应版本的成功单回合，不代替最终 S9 同源完整回归；本次也未重启此前暂停的长测。

## 生成与审阅产物

`scripts/build_ibero_presentation_v4.py` 生成 V4 并检查七段内嵌媒体字节与原视频摘要一致；原 V3 摘要生成前后保持一致。文稿依赖隔离在 `artifacts/pptx_tools/`，未升级仿真环境依赖。

`scripts/render_presentation.ps1` 使用本机 PowerPoint 只读打开、逐页导出并检查文字边界；`scripts/check_presentation_video_playback.ps1` 使用原生播放器检查播放时钟前进。脚本只关闭自己打开的文档，若用户已有 PowerPoint 进程则不退出其应用。

审阅记录与缩略图在 `artifacts/presentation_v4/`，构建来源、页码、视频摘要见 `build_manifest.json`。本次不修改仿真器、场景物性或用户的 `peng_readme.md`，也不自动推送 GitHub。

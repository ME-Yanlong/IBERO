# G1 固定钢板加工（S8 开发中）

这是左臂携带主轴、右臂安全停放的单臂加工工作站，不是双臂协同铣削，也不是钢材微观断裂模拟。目前在开发分支验证，不能把以下入口存在视为 G8 已通过。

## 菜谱怎样进入物理

`scene_config.yaml` → `core/plate_milling_config.py` 严格校验 → `envs/plate_milling.py` 组装 G1、主轴、支撑及实体体素毛坯 → `processes/milling.py` 以实际刀尖运动和剩余材料计算载荷/去除 → MuJoCo 积分 → `task_spec.py` 只读判断实际形状、退刀和停转。

材料、刀具、工艺系数和能力参数全部显式配置。采用与 `milling_bench` 相同的 `AISI1045-provisional` 系数，未做真实钢材标定。工作站额外采用 15 N 加工力限制，不通过缩小钢材系数适配机器人。固定工件的质量/剩余体积在材料账本；没有可随意释放的自由余料。

## 机器人与主轴

`robots/g1_milling.py` 使用原 G1 上身，卸下左按压头及原生手外观，安装有实体碰撞及质量的支架、主轴。右侧仍是 2F-85，不叠装灵巧手。`tip_offset_m` 是相对腕部的安装偏置，`stock_origin_m` 是世界坐标；初始刀尖和任务形状则以工件局部坐标声明。

reset 时才允许 IK 对齐及 seed 关节初态扰动。运行时 `control/milling.py` 通过原位置执行器下发期望力矩，包括重力补偿、位置/姿态阻抗；既不改 `qpos`，也不借外力通道直接驱动机器人。原关节范围、命令范围、肩肘 25 N·m / 腕 pitch、yaw 5 N·m 力矩限制保持不变。请求饱和锁存失败。

主轴拥有独立转子惯量和限矩电机。工具转子不能继承 G1 手臂的 0.3 N·m 干摩擦与 0.01 kg·m² 附加惯量；初版未标定轴承损耗，这一假设在工具构建处显式写明。进刀前必须看到真实主轴转速，不以经过固定秒数代替转速达标。

## 有界三轴，不是五轴

现实机器人不会严格保持零姿态误差。本菜谱允许最大 0.01 rad 刀轴偏差、0.1 rad/s 安装座角速度，同时要求有效刃区的投影几何误差小于四分之一体素。超限拒绝加工；更细网格会要求更严格姿态控制。载荷啮合仍采用近固定轴平均模型，几何扫掠保留真实姿态与安装座转动，不把机器人刀具强行扶正。

底层隐式耦合先用 MuJoCo 实测的局部响应求解，再以真实动力学复验。G1 的原生干摩擦、限矩等可能使响应非线性，此时转为独立 MjData 上的真实非线性残差求解；不取消摩擦或提高残差容差。求解失败时不提交新材料、不继续本步积分。

## 检查入口

```powershell
python scripts/verify_g1_milling_preflight.py
python scripts/diagnose_g1_milling_servo.py
python scripts/verify_milling_process.py --scene scenes/plate_milling --shape through_hole --workers 1
python -m pytest -q tests/test_plate_milling.py
python -m ibero.demo --env plate_milling --shape through_hole --viewer
python -m ibero.demo --env plate_milling --shape slot --viewer --no-visual-chips
python -m ibero.demo --env plate_milling --viewer --render-quality quality
```

上述第三条目前是单种子开发检查，不是完整 G8。报告会保存实际失败、材料轨迹、形状截面、独立动态探针，以及保存/加载/回看检查。探针使用真正加工后的占据与世界平移，不从目标生成理想孔；它属于独立检验台架，不冒充机器人在线持探针测量。

`constraints.yaml` 的 `volume_error_fraction` 与 `boundary_error_cells` 是实际裁判使用的阈值，可以收紧但不能超过冻结的 5% / 两格上限。例如将体积误差改成 1%，当前毫米网格的示例通孔会因约 3.45% 离散误差而不通过；收紧阈值不会自动细化网格或改变材料，需另外验证更细模型。

同一文件的 `max_seconds` 由底层加工时钟强制执行；`--steps` 只能提前结束 demo，不能延长场景时限。剩余预算不足一个物理子步时不再积分，超时锁存为失败并要求 reset，不用改步长或移动刀具补足剩余零头。

`python scripts/forecast_milling_geometry.py --scene scenes/plate_milling` 可先做无积分的名义网格体积预估，目标从这份场景的 P4 读取。它不提交删料，也不是加工成功检查；特别要注意加工深度与格距不对齐以及体素中心采样的非单调误差。真实力、孔洞碰撞及回放仍须单独运行。

预估中的 `candidate_recipe_valid/error` 另查原配置能否直接使用该格距：默认 0.5 mm 候选会因刀轴投影超过四分之一格而被拒绝，即使名义体积误差合格。工具不替用户调小姿态容差；静态配置合法也不是动态验收通过。

默认 `--render-quality fast` 只关闭显示阴影和地板反射；`quality` 可恢复这些效果，不改变材料、接触或物理步长。前三格依次为全景、刀具局部、毛坯检查俯视；第三格只在独立显示副本隐藏机器人/刀具，以免刀具遮住孔洞。第四格为实际占据 XZ 剖面及全回合载荷需求峰值，不把超限拒绝的候选载荷当成已施加外力。C 可关闭纯视觉切屑。

当前验收机的 OpenGL 使用 Intel 核显，虽然设备中也有 RTX 5080 Laptop GPU；不能据设备列表假定已经使用独显。工程性能报告会记录实际 OpenGL renderer、并发负载和各项耗时，项目不自动修改系统显卡偏好。fast 不是物理加速选项；目前完整细步长任务依然明显慢于实时。

## 尚待闭合

加工专用持久四视图和可关闭视觉切屑已实现，短程真实 GUI 交互及显示隔离检查通过。默认机器人通孔、直槽与浅腔已在冻结检查点完成单次全链通过；跨种子 G8、系数变体、两次完整成功 GUI、全量最终回归仍须证据闭合。台架已通过不代表机器人已通过；截图和控制器走完也不能单独让任务成功。具体版本见开发日志 §18，后续源码修改不能冒用旧轨迹身份。

并行验收默认保持少量进程，不建议同时启动多组长测。Windows 启动检查使用**可提交内存额度**，不是只看空闲物理 RAM；估算每个工作进程 1.5 GiB 并另留 2 GiB 余量。不足时在 `resource_preflight.json` 留下记录并非零退出，等待已有任务结束或减少 `--workers` 后使用新输出目录重跑。这个估算不是峰值保证，不修改系统页面文件或显卡配置；其它系统目前明确记录资源检查未覆盖。

新验收 worker 缺省使用单线程数值库，避免每个进程额外建立一组 OpenBLAS 线程与工作缓冲区；仅在 `OPENBLAS_NUM_THREADS`、`OMP_NUM_THREADS`、`MKL_NUM_THREADS` 都未设置时生效，有任意显式配置则完整保留。它只影响随后启动的子进程，不热修改已加载库或系统环境。短加工前缀的逐帧等价与完整测试已检查，但不宣称所有软件/硬件上数值行为永远一致；报告记录实际传入的环境变量及 NumPy/Python 版本。1.5 GiB 的保守启动估算暂不因此降低。

### 载荷诊断与数值边界

内层阻抗目前每物理步更新（100 μs，即仿真 10 kHz），高层路径仍为 100 Hz；不是声称真实 G1 SDK 有这一频率。原 1 kHz 与 10 kHz 的过载反例均保留。端面啮合不能只用“是否扫到新的体素中心”判断：斜向微进给可能在层间产生短暂中心空隙，而既定一格端面前视仍看到下层材料。端面面积同时遵守可切列中心条件，防止完整孔边缘的不可提交格产生持续伪载荷。原始失败与修正验收参见开发日志 §18.18。
